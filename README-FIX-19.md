# `FIX-19` — `found` возвращался только при неудаче

Последний красный пример `EVAL-1`. И это снова дефект инструмента, а не
моего ожидания.

```powershell
docker compose build mcp-metadata-graph
docker compose up -d --no-deps --force-recreate mcp-metadata-graph
python scripts\eval.py --dataset evals/datasets/metadata_graph.jsonl
```

---

## Что показал отчёт

```json
{"path": "found", "expected": true, "actual": null, "found": false}
```

`actual: null` — ключа `found` в ответе нет вовсе. При этом второй предикат
(`non_empty`) **прошёл**: реквизиты вернулись.

То есть `metadata_object_attributes` на успешном ответе отдавал состав
объекта и молчал про `found`, а на неудачном писал `found: false`.

**Хорошая новость:** это же доказывает, что `FIX-18` работает. Запрос шёл
по русской форме `Справочник.ЭдоОбщийУчастникиДО`, и объект нашёлся.

## Почему это не придирка

Агент, проверяющий `found`, на успешном ответе получает `null` — то есть
ложь. Он может заключить, что объекта нет, притом что состав лежит рядом,
в том же ответе.

Асимметричный признак хуже отсутствующего: отсутствующий заставит смотреть
на данные, а этот выглядит надёжным.

## Что исправлено

`"found": True` добавлено в успешные ответы `metadata_object_attributes` и
`metadata_referrers` — тех, у кого была только отрицательная ветка.

Новый контрактный тест `TestFoundFlagSymmetry`: если в файле есть ветки
`found: False`, положительных должно быть не меньше. Грубо, но ловит
именно этот перекос.

639 тестов.
