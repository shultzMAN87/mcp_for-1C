## 1. `WARNING → reindexed` — оказалось не косметикой

`upsert_file` возвращает статус `reindexed`, а код ждал `ok`/`updated`/
`created`. Но за этой мелочью нашлось существенное: **`upsert_xml_file`
умеет только верхнеуровневые XML объектов**. Вложенные — формы, макеты —
возвращаются со статусом `skipped`.

У вашей обработки 11 файлов. Из них обрабатывается один XML плюс модули;
остальные десять давали бы по строке «предупреждения» о нормальном
поведении на каждом прогоне.

Стало: вложенные XML отсеиваются заранее (`is_upsertable`), а не
отправляются в базу ради отказа — это ещё и десять лишних обращений по
сети на каждый объект. В `--dry-run` теперь видно реальное число:

```
обновить DataProcessor.ЭдоРаботаСЭП (2 файлов, вложенных пропущено 9)
```

На полноту это не влияет: правка формы меняет отпечаток **родительского**
объекта, а вместе с ним переобновляются модули форм — там и читаются
реквизиты формы, нужные резолверу.

Неожиданный пропуск (файл есть, а обновление до него не дошло) теперь
считается ошибкой, а не молча пропускается: иначе объект остался бы в
графе старым, а прогон отчитался бы об успехе. Принцип `FIX-15`.

## 2. Раннер `evals` не понимал ответы metadata-graph

`predicates._hits` искал список только в ключе `results`. Так отвечают
platform-help, v8std и bsl-checker. А metadata-graph отдаёт **`items`**.

То есть весь датасет `metadata_graph.jsonl` провалился бы целиком, и
выглядело бы это как «инструменты сломаны» — хотя сломан был бы раннер.
Хорошо, что это нашлось до запуска, а не после.

Ключи проверяются по порядку, первый найденный список выигрывает:
складывать нельзя, иначе ответ с обоими ключами задвоился бы.

## 3. `CI-1` не находил набор раннера

Я писал, что «наборы находятся сами». Это оказалось верно только для того
каталога, о котором я думал: `evals/runner/tests.py` не подпадает под
маску `tests_*.py` и **не запускался ни разу**.

Теперь ищется и он. Но вне своего контейнера он требует пакет `mcp`,
поэтому выводится отдельной строкой:

```
НЕТ  tests.py    не запускался — нужен пакет 'mcp' (набор живёт в своём контейнере)

Не проверялись (нет зависимостей вне контейнера):
    evals/runner/tests.py — нужен 'mcp'
    Запуск: docker compose run --rm eval-runner python -m pytest
```

Не провал и не успех — «не проверялся», сказанное прямо. Молча пропускать
такое было бы ровно тем, за что я критиковал прежний код.

## Дальше — запуск EVAL-1 и BASE-1

Оба ни разу не запускались.

```powershell
python scripts\check_baseline.py --update
```

Создаст `evals/baseline.json` из текущего состояния графа. Делать это
нужно сейчас, пока граф заведомо соответствует выгрузке.

```powershell
python scripts\eval.py --dataset evals/datasets/metadata_graph.jsonl
```

16 примеров. **Прочтите шапку датасета перед первым прогоном**: примеры
засеяны вашими же ответами из приёмки, но это проверка человеком один раз,
а не эталон. Где предикат упадёт — сначала смотрите, кто неправ,
инструмент или ожидание.

Ожидаю, что часть примеров упадёт: числа привязаны к состоянию графа, а
имена объектов я брал из наших разговоров. Это нормальный первый прогон
датасета, его и надо довести до зелёного.
