# TR-2, вторая попытка. В Заходе 1 `fastmcp` убрали из requirements.txt, но
# этот файл не тронули — и всё это время в образ platform-help ставились
# ОБЕ реализации: официальный SDK (`mcp[cli]`, откуда код берёт
# `mcp.server.fastmcp`) и отдельная библиотека `fastmcp` проекта jlowin с
# классом того же имени. Ровно тот риск, ради снятия которого правку
# делали, остался жив в одном из трёх образов.
#
# Второе: у `mcp` здесь стояла граница `>=1.0.0`. Streamable HTTP и
# параметр `stateless_http` появились в SDK 1.9, а на этом образе работает
# `mcp-platform-help` через общий `mcp_http.py`. То есть сборка с нуля
# могла приехать на версии, где `streamable_http_app()` просто нет.
#
# Верхние границы по мажорам — чтобы пересборка через полгода не уехала на
# другой мажор молча. Точная фиксация — в requirements-embeddings.lock.txt,
# см. `make lock`.

# ─── PERF-11. torch без CUDA ──────────────────────────────────────────
#
# Чистая пересборка 17 августа скачала ~2,5 ГБ колёс `nvidia-*` и `triton`.
# Их тянет `torch`: в сборке по умолчанию для linux/x86_64 CUDA-рантайм
# объявлен обязательной зависимостью, независимо от того, есть ли на машине
# GPU.
#
# На стенде GPU не проброшен. То есть в образе лежат два с половиной
# гигабайта, которые не выполняются ни разу, — та же болезнь, что у
# `pymupdf` (`DOC-2`), только весом в две тысячи раз больше. Цена: время
# сборки, размер образа, время выкачивания на каждой чистой машине.
#
# Лечится индексом CPU-сборок. Локальная версия `+cpu` по правилам PEP 440
# считается СТАРШЕ обычной `2.x.y`, поэтому при двух индексах побеждает она
# — отдельно закреплять версию не нужно.
#
# ⚠️ Строка ниже имеет смысл только через `make lock`: она попадает в
# заголовок лок-файла, и уже оттуда её читает `pip install` при сборке
# образа. Правка этого файла БЕЗ пересборки лока не меняет ничего —
# `Dockerfile.embeddings` ставит по локу, а не отсюда.
--extra-index-url https://download.pytorch.org/whl/cpu
