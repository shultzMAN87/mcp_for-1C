# evals/datasets — наборы запросов для eval-runner

Один файл — один датасет. Формат: JSONL (одна JSON-строка на пример) с допущением, что строки `//...` и пустые строки пропускаются.

Полное описание формата и всех типов предикатов — [../schema.md](../schema.md).

## Как добавить свои запросы

1. Открой `platform_help.jsonl` и посмотри на 10 существующих примеров — там есть все типы предикатов, скопируй подходящий шаблон.
2. Новые примеры — новые строки в конец файла (или новый файл в этой папке).
3. Запусти runner:
   ```bash
   docker compose --profile evals run --rm eval-runner
   ```
   Или с хоста без docker:
   ```bash
   python3 scripts/eval.py
   ```
4. Открой свежий отчёт в `evals/reports/`, посмотри, что реально попадает в топ. Если очевидная ошибка датасета (название метода не существует или оно в другом регистре) — правь `values` в предикате.

## Что писать в `values` и где это взять

В `name_in_top_k.values` попадают RU/EN имена так, **как они хранятся в Qdrant**. Проще всего узнать — сделать временный пример с одним `non_empty` и посмотреть `response_preview.results[]` в JSON-отчёте:

```bash
# Создаём однострочный датасет-пробу
echo '{"id":"probe","tool":"platform_help_search","args":{"query":"разделить строку","limit":5},"expect":{"hard":[{"type":"non_empty"}],"soft":[]}}' \
  > evals/datasets/probe.jsonl

# Запускаем только его
python3 scripts/eval.py --dataset evals/datasets/probe.jsonl

# В evals/reports/probe_*.json смотрим summary.examples[0].response_preview.results[]
# Там увидишь реальные name_ru / name_en / full_name — скопируй в values своего настоящего примера.
```

## Советы

- **Hard-предикаты — только там, где эталон однозначен.** Если запрос размыт («как ускорить код»), не ставь `name_in_top_k` в hard, перенеси в soft — иначе будешь ловить ложные регрессы при любом безобидном изменении поиска.
- **`non_empty` в hard для каждого примера** — самая дешёвая и полезная проверка. Если она начала падать — что-то сломалось в пайплайне, а не в качестве поиска.
- **Запросы реалистичные.** Цель датасета — мерить, не деградирует ли поиск **на тех запросах, которые реально задают пользователи**. Не копай синтетику.
- **Коротко — нормально.** 30-50 запросов с адекватным ground truth полезнее 500 «лишь бы было».
