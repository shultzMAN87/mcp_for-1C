# `PERF-8`, исправление — запись отпечатков падала по таймауту

Патч поверх шага 1. Обход выгрузки отработал верно (24 795 единиц,
53 785 файлов, 12,5 мин), а запись в граф — нет.

```powershell
docker compose build metadata-indexer mcp-metadata-graph mcp-query-builder workspace-watcher
docker compose run --rm --entrypoint python metadata-indexer /app/what_changed.py --save
```

---

## Что было не так

В `write_stored` стоял запрос **без метки**:

```cypher
UNWIND $rows AS r
MATCH (n {id: r.id})
SET n.fp = r.fp
```

Констрейнты — а значит, и индексы по `id` — привязаны к меткам. Матч без
метки индекс использовать не может и перебирает все 1,3 млн узлов графа на
**каждую** строку `UNWIND`. При 24 795 строках это порядка 32 миллиардов
сравнений; Neo4j отвалился по таймауту, не записав ничего.

Это `PERF-4` в третий раз — та самая ошибка, с которой начинался Заход 4.
И два отягчающих обстоятельства, которые стоит назвать прямо:

1. **Я написал себе оправдание в комментарии** — «раз в прогон, цена
   несопоставима с горячим путём» — вместо того чтобы посчитать. Арифметика
   оправдание не подтверждает.
2. **Я обошёл собственную защиту.** Контрактный тест ищет шаблон
   `(переменная {id:`, и в комментарии к коду я отметил, что «здесь
   переменной нет намеренно, чтобы не сработать ложно». То есть подогнал
   код под тест, а не наоборот.

## Что исправлено

**Запись идёт двумя запросами по меткам.** Каждый владелец — это узел
`:MetadataObject` (объекты, общие модули, модули объекта и менеджера) либо
`:Form` (модули форм: `write_form_nodes` создаёт форму как `:Form`, а фаза
2 лишь дописывает ей `:Module`). У обеих меток есть констрейнт на `id`, то
есть индекс. Метку `:Module` использовать нельзя — индекса на ней нет, был
бы тот же полный перебор.

**Считается записанное, а не отправленное** — принцип `FIX-15`. Если
владелец есть в выгрузке, но узла в графе нет, в лог идёт предупреждение с
числом: по таким объектам частичное обновление не сработает.

**Контрактный тест расширен на каталог индексатора.** Мой дефект проскочил
ровно потому, что тест смотрел только в каталог серверов, — а дефект,
от которого он защищает, каталогами не ограничен. Проверил возвратом
дефекта в код: ловится, с указанием файла и строки.

## Тесты

`tests_partial_fingerprint.py` — 33 теста (было 26), `tests_graph_contract.py` —
8 (было 7). Всего 620.

Стаб Neo4j в новых тестах ведёт себя как настоящая база: `MATCH` по метке
находит только узлы с этой меткой. Наивный стаб, отвечающий «нашлось всё»,
одинаково пропустил бы и правильный запрос, и тот, что перебирает базу
целиком, — то есть был бы бесполезен ровно там, где нужен.

## Про 2 625 пропущенных файлов

В выводе обхода: `файлов 53785 (пропущено 2625)`. Это `.xml`, не
принадлежащие ни объекту, ни модулю, — при 56 410 файлах всего сходится.
Скорее всего `Ext/*.xml` в нераспознанных видах и содержимое каталогов,
которых нет в таблице `KINDS`. На работу это не влияет (такие файлы
индексатор и так не читает), но если после `--save` обычный запуск покажет
не «изменений нет», а что-то другое — начинать разбираться надо отсюда.
