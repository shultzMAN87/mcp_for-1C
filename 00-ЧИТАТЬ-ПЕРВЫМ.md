# Что в архиве и куда это класть

Дерево внутри архива повторяет структуру проекта `30_mcp_cursor`. Можно
распаковать поверх корня проекта — все пути совпадут. Ниже — что именно
меняется, чтобы было понятно, что вы перезаписываете.

Обоснование решений и отклонений от `PLAN-STD.md` — в `ИТОГИ-STD.md`.
Прочитать стоит до применения: половина плана отменена сознательно.

**Про `.cursor/mcp.json`.** Файл взят из вашего архива вместе с
вписанным в него bearer-токеном — то есть перезапись безопасна. Но файл в
`.gitignore`, и если ваша рабочая копия успела разойтись с той, что была в
архиве, добавьте блок `v8std` руками:

```json
"v8std": { "url": "http://127.0.0.1:8765/mcp" }
```

Заголовка авторизации у него нет намеренно: сервер чужой и нашу схему не
знает.

## Применяется отдельно

`optional-ubrat-its/` — удаление мёртвой ветки ИТС из `platform-help`.
Единственная необратимая правка набора, вынесена по вашему вопросу.
Инструкция внутри, в `optional-ubrat-its/README.md`. Разумный порядок:
сначала поднять `v8std-mcp` и убедиться, что стандарты достаются, потом
убирать то, что они заменили.

## Порядок применения

```powershell
# 1. Распаковать поверх корня проекта

# 2. Забрать корпус (сеть нужна только здесь)
python scripts/fetch_v8std.py
python scripts/fetch_v8std.py --check

# 3. Поднять пятый сервер
docker compose up -d --build v8std-mcp
docker compose ps v8std-mcp

# 4. Пересобрать bsl-checker — там правка STD-5
docker compose up -d --build mcp-bsl-checker

# 5. Проверить состав инструментов (у v8std ожидается 5)
python scripts/list_tools.py

# 6. Прогнать датасет
python scripts/eval.py --dataset evals/datasets/v8std.jsonl

# 7. Перезапустить Cursor, чтобы он перечитал .cursor/mcp.json
```

Если сеть у вас идёт через системный прокси, экспортируйте `HTTPS_PROXY`
перед шагом 2. Шаг 2 можно и пропустить — тогда сервер возьмёт индекс с
v8std.ru сам при старте, но ему понадобится сеть и прокси уже внутри
контейнера (закомментированные строки в сервисе `v8std-mcp`).

## Что проверено, а что нет

Проверено локально: синтаксис всех файлов, валидность `docker-compose.yml`
и JSON-конфигов, работа `fetch_v8std.py` (полный цикл, включая манифест,
идемпотентность и путь отказа), логика точки входа контейнера (сборка
аргументов и fail-closed с кодом 78), новые предикаты, формирование
`std_lookup` в bsl-checker, валидность датасета.

Не проверено: живой прогон на вашем стеке — доступа к нему нет. Датасет
написан, но не откалиброван: на «человеческих» формулировках ожидаемые
номера стандартов стоят в `soft` именно поэтому. Правьте `values` по
первому отчёту, а не наоборот.
