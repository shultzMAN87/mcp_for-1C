# Контракт `affects` — единственная точка стыка со спеками

Контур документации не знает, чем у вас порождаются спеки: генератором
фреймворка, шаблоном в вики или руками в блокноте. Он знает одно поле и
умеет прочитать его из трёх форм записи.

Это сделано намеренно. Инструмент управления спеками — самая недолговечная
часть процесса: его меняют чаще, чем язык, редактор и трекер. Контур,
завязанный на конкретный фреймворк, пришлось бы переписывать вместе с ним.

## Что требуется от вашего процесса

Одно: чтобы в спеке был список объектов метаданных, которых коснулась
задача. Имя поля — `affects` (принимаются также `затронутые_объекты` и
`touches`). Формат имён совпадает с `targets` во фронтматтере документа:
канон `full_name_eng`, но на входе принимаются все три формы, как везде в
наборе.

## Три формы записи, любая подойдёт

**1. Фронтматтер, если он у вас есть:**

```markdown
---
id: SPEC-142
affects:
  - Catalog.Контрагенты
  - CommonModule.ОбменМП
---
```

**2. Файл целиком как YAML или JSON:**

```json
{ "id": "SPEC-142", "affects": ["Catalog.Контрагенты", "CommonModule.ОбменМП"] }
```

**3. Раздел в markdown — для форматов без фронтматтера:**

```markdown
## Affects

- Catalog.Контрагенты
- CommonModule.ОбменМП
```

Заголовок ищется по смыслу: подойдёт `Affects`, `Затронутые объекты`,
`Touches`, `## Что затронуто`. Пункты следующего раздела в список не
утекают. Внутри блока кода список тоже читается.

## Как это работает

```
python scripts\docs_affects.py спека.md
python scripts\docs_affects.py спеки\*.md --queue
```

Скрипт достаёт список, сверяет имена со словарём из графа (имя вне словаря —
ошибка, а не замечание: иначе поле молча зарастает опечатками), находит
документы, у которых `targets` пересекается с `affects`, и ставит их в
очередь ревизии.

Если ни один документ не покрывает затронутые объекты — это тоже результат:
кандидат на заявку в очередь заявок.

## Почему Definition of Done формулируется именно так

Не «обновить документацию» — такое требование не проверяется и потому не
выполняется. А «заполнить `affects`» проверяется одной командой с ненулевым
кодом возврата, и именно поэтому выполняется.

Заполняет поле агент по диффу в конце задачи, человек проверяет при приёмке.

## Если появится четвёртый формат

Добавляется одна функция в `scripts/docs_affects.py` рядом с
`from_frontmatter`, `from_whole_file`, `from_section`, и одна строка в
список стратегий. Остальной контур не шелохнётся — он получает уже
канонический список имён и про источник ничего не знает.

Набор `scripts/tests_docs_affects.py` держит это свойство: там перечислены
форматы, а не продукты. Список продуктов в этих тестах — признак того, что
привязка вернулась.

## Второе требование к процессу, не машинное

В спеке полезно фиксировать расхождения замысла с реализацией: что
планировали, что получилось, почему. Это единственный источник таких
сведений — ни в коде, ни в самой спеке их нет. Строки уезжают в раздел
«Решения» соответствующего документа.

```
- Планировали регистр сведений, сделали реквизит: история значений не понадобилась.
- Метод /orders/{id} остался синхронным: очередь не успели.
```
