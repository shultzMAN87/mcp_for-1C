# Как забрать новую выгрузку из корпоративного GitLab

Выгрузка из хранилища приходит в GitLab раз в час. Чтобы граф увидел её,
нужно подтянуть клон `ubd_for_ai` и доиндексировать изменения. Пути ниже —
как на стенде; подставьте свои (`WORKSPACE_DIR` в `.env` стека).

## 1. В `src` нет своих правок

```powershell
cd D:\projects\Cursor\ubd_for_ai
git status --short
```

**Ожидание:** пусто. Если есть правки (уже в хранилище или больше не
нужны) — вернуть `src` к канону; правки не удаляются, а уходят в
`git stash`:

```powershell
D:\Docker\mcp_for-1C\scripts\restore-src-canon.ps1
```

## 2. Есть ли что забирать

```powershell
git fetch
git log --oneline HEAD..origin/main
```

**Ожидание:** список коммитов «Выгрузка конфигурации…». Пусто — новых
выгрузок нет, дальше идти незачем. Строка `warning: redirecting to …` —
норма, это переадресация GitLab.

## 3. Подтянуть

```powershell
git pull --ff-only
```

**Ожидание:** `Fast-forward` и список файлов. Отказ означает, что в
локальной ветке есть свои коммиты — в схеме «правки → хранилище → GitLab»
их быть не должно, сначала разобраться.

Шаги 2–3 делает и корпоративный `ubd-git-sync`; он сам откажется тянуть
при грязном `src`.

## 4. Обновить граф

**Watcher включён** (`WATCHER_ENABLED=true` в `.env` стека) — ничего делать
не нужно: за `SOURCE_POLL_SEC` (минуту) он увидит новый коммит и
доиндексирует изменённые файлы. Видно в `docker logs -f workspace-watcher`.

**Watcher выключен** — вручную:

```powershell
cd D:\Docker\mcp_for-1C
.\scripts\graph-refresh.ps1
```

**Ожидание:** `ИТОГ: ok — обновлено файлов: N; HEAD <старый>→<новый>`,
затем `Готово.` и путь к логу. Секунды или пара минут.

Если скрипт ответил «нужна полная индексация» (изменилось больше 300
объектов — например, неделю не подтягивали):

```powershell
.\scripts\graph-refresh.ps1 -Full
```

Около 10 минут.

## 5. Проверить, что граф свежий

```powershell
.\scripts\graph-refresh.ps1 -DryRun
```

**Ожидание:** `будет обновлено файлов: 0, HEAD <новый>→<новый>`.

Из чата с агентом то же показывает `metadata_stats` → блок `source`:
`in_sync: true`, `dirty_count: 0`.

## Если хотите проверить глубже

Вместо шага 4 — скрипт, который сам доиндексирует и сверит каждый
изменённый модуль с файлом (процедуры, строки, вызовы), итог
ПРОЙДЕНО/ПРОВАЛ, протокол в `logs\`:

```powershell
.\scripts\check-graph-refresh.ps1 -SkipScenario2
```

## Коротко

| Шаг | Команда | Ожидание |
|---|---|---|
| `src` чистый | `git status --short` | пусто |
| есть что забирать | `git fetch`, `git log --oneline HEAD..origin/main` | список коммитов |
| подтянуть | `git pull --ff-only` | `Fast-forward` |
| граф | watcher сам или `.\scripts\graph-refresh.ps1` | `ИТОГ: ok` |
| проверка | `.\scripts\graph-refresh.ps1 -DryRun` | 0 файлов, `HEAD <новый>→<новый>` |
