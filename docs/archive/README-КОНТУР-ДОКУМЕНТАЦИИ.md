# Куда распаковать и как этим пользоваться

**Этот архив заменяет оба предыдущих целиком.** Первые два больше не нужны:
файлы из них здесь же, только исправленные. Ничего доустанавливать поверх не
надо.

---

## Шаг 1. Распаковать

Архив повторяет структуру `30_mcp_cursor/`, поэтому распаковывается в корень
репозитория — туда, где лежат `docker-compose.yml` и `README.md`. У вас это,
судя по документации набора, `D:\Docker\30_mcp_cursor`.

```powershell
cd D:\Docker\30_mcp_cursor
# распакуйте архив сюда, с сохранением путей
```

Появятся новые каталоги `techdocs\`, `schema\`, `integration\`, новые файлы
в `scripts\` и `docker-compose.confluence.yml` в корне. **Ни один существующий
файл не перезаписывается** — проверьте перед распаковкой, что архиватор не
предлагает замену: если предлагает, что-то пошло не так.

Если первый архив вы уже распаковывали, удалите то, что он оставил:

```powershell
Remove-Item -Recurse docs\process, docs\http-service, docs\object,
                     docs\_proposed, docs\_imported, docs\_queue
Remove-Item docs\README.md, docs\names.example.json
```

Корпус переехал в `techdocs\`: каталог `docs\` у вас занят документацией
самого набора, и его состав стережёт `scripts\tests_docs_canon.py`.

## Шаг 2. Зависимости

```powershell
pip install pyyaml jsonschema
```

`httpx` уже стоит как зависимость MCP SDK. Драйвер Neo4j не нужен: в базу
ходим по HTTP через `/db/neo4j/tx/commit`, как остальные серверы набора.

## Шаг 3. Секреты

`.env.example` и `.gitignore` в архиве — **единственные два файла, которые
перезаписывают существующие**. Это ваши файлы целиком, с дописанной секцией
в конце; ничего из прежнего содержимого не потерялось. Сверьте diff перед
принятием, если правили их с момента, когда присылали архив.

Многие архиваторы по умолчанию не показывают файлы, начинающиеся с точки —
проверьте, что оба легли на место.

Дальше скопируйте новые строки из `.env.example` в свой `.env` и заполните:

```
CONFLUENCE_BASE_URL=https://confluence.company.ru
CONFLUENCE_TOKEN=
CONFLUENCE_USER=                 # пусто для Data Center
CONFLUENCE_DB_PASSWORD=          # только для тестового Confluence в Docker
CONFLUENCE_IMAGE_TAG=            # версия вашей установки
```

Проверено на живом git: `techdocs/names.json`, `techdocs/_imported/*`,
`logs/`, `inventory.json` и отчёт пробника игнорируются, а `_queue/*.jsonl`
и `.gitkeep` — нет. Очереди отслеживаются намеренно: конфликт R4 без
истории зависает, а двухнедельный срок разбора иначе нечем измерить.

## Шаг 4. Проверить, что всё встало

```powershell
python scripts\run_all_tests.py --quiet
```

Должно прибавиться три набора: `tests_docs_validate`, `tests_docs_migration`
и `tests_docs_affects`. У меня это 1286 тестов вместо 1264.

## Как этим пользоваться

### Каждый день — только одна команда

```powershell
python scripts\docs_validate.py
```

Она проверяет корпус перед коммитом. Ненулевой код — коммитить нельзя.
Если ругается на имена, `--fix` приведёт их к канону сам.

Отдельно запускать её не обязательно: она входит в `run_all_tests.py`.

### После закрытия задачи

```powershell
python scripts\docs_affects.py спека.md --queue
```

Читает список затронутых объектов из спеки и ставит в очередь ревизии
документы, которых это касается. Формат спеки безразличен — см.
`integration\affects-contract.md`.

### Раз в неделю или после переиндексации графа

```powershell
python scripts\docs_names_dump.py
```

Обновляет словарь имён из Neo4j. Без него валидатор не проверяет `targets`,
а только предупреждает.

### Один раз, чтобы закрыть Р-1

```powershell
docker compose -f docker-compose.confluence.yml up -d
python scripts\confluence_probe.py --space TECHDOC
```

Первый старт Confluence — 3–7 минут, дальше мастер настройки на
http://localhost:8090. Понадобится пробный лицензионный ключ Atlassian; если
ходить за ним с этой машины нельзя, тестовый контур отпадает, и пробник
надо гонять против тестового пространства боевого Confluence.

Пробник без `--write` не делает ни одного запроса на запись. Он сам скажет,
Cloud перед ним или Data Center, померит скорость обхода, проверит, доступна
ли статистика просмотров, и запишет заголовки лимитов в
`logs\confluence_ratelimit.jsonl`.

С `--write --cleanup` он дополнительно выяснит три вещи, которые иначе
всплывут поздно: переживает ли кириллица заголовок и тело (R9), плодит ли
повторная запись тем же телом новую версию (R3), отклоняет ли сервер
устаревший номер версии.

## Блок H: как это выглядит в работе

Готова читающая половина конвейера — шаги 1–8 из 6.2. Она **не пишет в
Confluence ни одного байта**: клиент во всех трёх скриптах создаётся с
`allow_write=False`, то есть запись невозможна механически, а не по
договорённости.

### Шаг первый: сколько у вас legacy на самом деле

```powershell
python scripts\docs_inventory.py --space TECHDOC --sample 30
```

Отдаёт: сколько страниц, какого возраста, сколько похоже на техническую
часть по заголовку, кто последний правил, какие метки в ходу, и по выборке —
насколько богато оформлены и что в них есть такого, чего конвертер не берёт.

Этот отчёт и есть основание решить, нужна ли кампания. Вполне возможен
исход, при котором технических страниц полсотни, живых полтора десятка, и
весь блок H сводится к дню ручной работы. Это хороший результат, и узнать
его надо до конвертера, а не после.

### Шаг второй: разбор и карточки

```powershell
python scripts\docs_import.py --space TECHDOC --limit 20 --graph
```

По каждой странице кладёт в `techdocs\_imported\`:

| Файл | Что |
|---|---|
| `<page_id>.txt` | исходник дословно, до всякого разбора |
| `<page_id>.card.txt` | карточка для человека |
| `<page_id>.card.json` | она же для машины |
| `<page_id>.comments.txt` | комментарии страницы (DOC-37) |

Карточка выглядит так:

```
Страница: Обмен с маркетплейсом (page_id 3948112)
Обновлена: 2024-11-03, автор petrov
targets: Catalog.Контрагенты, CommonModule.ОбменМП
не найдено в графе: РегистрСведений.ОчередьОбмена

Утверждений: 5   подтверждено 0 / противоречит 1 / нет объекта 1 / не проверяемо 3

Расхождения (в статье А, в конфигурации Б — кто прав, решает человек):
  - «Пишем в РегистрСведений.ОчередьОбмена, читаем из Справочник.Контрагенты.»
    в конфигурации таких объектов не найдено

Не проверяемо (3) — сохранить дословно:
  - «Обмен запускается регламентным заданием раз в 15 минут, иначе заказы копятся.»
  - «Токен живёт 24 часа, продлевать вручную нельзя»
  - «От очереди отказались в 2024: нагрузка не оправдала сложности.»

Вердикт: решает человек: сначала разобрать расхождения ниже
```

Вердикт в последней строке — подсказка, а не решение. Машина берёт его на
себя только в механических случаях: страница не разобралась, или в ней есть
draw.io, или в ней ноль непроверяемых утверждений (значит, она состоит из
производного, и мигрировать нечего).

### Шаг третий: человек

Работа человека — четыре решения на карточку: вердикт по странице, разбор
расхождений, проверка, что ценное не выхолощено, приёмка диффа. Пятнадцать
минут на карточку, если он знает предметную область.

Расхождения не правятся автоматически осознанно. «Объекта нет в
конфигурации» означает одно из трёх: статья устарела, статья описывает
целевое состояние, или в коде дефект. В третьем случае «приведение
документации в соответствие с кодом» задокументирует баг как норму.

### Предохранитель от главного риска блока H

Агент, разбирая статью, склонен оставить подтверждённое и убрать
неподтверждённое — то есть ровно то, ради чего документация существует.
Статья становится аккуратнее и беднее, и заметить это почти невозможно.

Проверка машинная, а не в промпте:

```powershell
python scripts\docs_classify.py --card techdocs\_imported\3948112.card.json ^
                                --check-draft черновик.md
```

Каждый фрагмент «не проверяемо» обязан присутствовать в черновике
**дословно**. Перефразировка не считается сохранением, и черновик
отклоняется с ненулевым кодом. Проверено тестом: аккуратный пересказ
«Обмен нужен для работы с маркетплейсом» вместо «Обмен придумали ради
маркетплейса, иначе заказы заводят руками» — это отклонение.

## Что готово и что дальше

Готово: блок A целиком (DOC-1, 2, 3, 4, 38), связь со спеками (DOC-20),
ядро DOC-39, пробник DOC-5, читающая половина блока H (DOC-30, 31, 32, 33,
37) и проверка R15.

Ни один скрипт не знает про фреймворк спек, редактор и агента. Единственная
точка стыка — поле `affects`, читаемое из трёх форм записи. Git нужен только
одной проверке в валидаторе и отключается флагом `--no-git`.

Не начато и почему:

- **Публикующая половина блока H (DOC-34, 35, 36).** Включается, когда
  появится человек на разбор карточек. Пока его нет, публиковать некому и
  незачем: карточки без читателя — просто файлы на диске.
- **Каркас `mcp-docs` (DOC-10) и весь блок C.** Требует правок в трёх ваших
  файлах: порт в `SERVERS` у `start.py`, секция в `docker-compose.yml`,
  строка в `Dockerfile.python`. Скажите, свободен ли порт 8010 и можно ли
  трогать общие файлы.
- **Блок B (публикация).** Ждёт результата пробника: до ответа на Р-1
  конвертер markdown → storage format не на что калибровать.
