# AUDIT-2. Что уже решено правильно — и не распространено

Дата: 15 августа 2026.

## Зачем этот аудит

`AUDIT-1` задавал вопрос «чего не хватает». За заход по `PLAN-5` трижды
выяснилось, что нужное решение уже лежало в проекте — сделанное в одном
месте и не разошедшееся по остальным:

| Что нашлось | Где было | Где не было |
|---|---|---|
| `answerable: false` + `meaning` | `graph_state.py`, `FIX-3` | у трёх серверов из пяти |
| «отправлено против записанного» | `graph_writer._warn_shortfall` | у всех парсеров и читателей |
| отказ при `GRAPH_UNAVAILABLE` | `metadata_stats`, `FIX-3` | у одного инструмента из двадцати девяти |

Каждый раз распространить готовое оказывалось дешевле, чем писать заново, и
безопаснее: решение уже обкатано.

Отсюда обратный вопрос, которому посвящён этот аудит: **что в проекте
сделано правильно ровно в одном месте?** Ниже — семь находок, по убыванию
цены.

Формат прежний: `диагноз` — `цена` — `оценка`.

---

## B-1. Быстрый отказ есть только у справки

**Диагноз.** `FAIL-1` научил `platform-help` не ждать таймаутов, когда
известно, что Qdrant лежит: `_qdrant_down_now()` смотрит на кешированный
вердикт и возвращается мгновенно. Замер подтвердил — 7 916 мс → 102 мс.

У `metadata-graph` и `query-builder` такого нет вовсе. `make_guard()`
опрашивает Neo4j **на каждом вызове инструмента**, вердикт нигде не
кешируется. Замер 15 августа при остановленной Neo4j: восемнадцать
примеров, каждый по 3 850 мс, и это не худший случай — инструментов
двадцать девять.

**Цена.** В чате с Cursor при лежащей Neo4j каждый вызов
`metadata_search`, `code_callers`, `query_fields` стоит четыре секунды
тишины. Ровно тот исход, ради которого чинились `FIX-14` и `FAIL-1`:
агент считает инструмент неотвечающим и уходит отвечать по памяти. Сервер,
где это исправлено, — самый маленький из трёх; сервер, где не исправлено,
— самый большой и самый вызываемый.

**Что делать.** Перенести `_qdrant_down_now()` в общий вид: кешировать
вердикт `graph_state` на короткое окно (те же тридцать секунд), сбрасывать
по успеху. Место готовое — `make_guard()` в `graph_state.py`, через него
проходят двадцать девять точек вызова:

```
server.py                 10
server_v3_tools.py         9
server_v3_code_tools.py   10
```

**Осторожно, ловушка внутри находки.** `query-builder` до `make_guard` не
дошёл — у него свой `_guard()` с телом, скопированным дословно:

```python
def _guard():
    state, detail = graph_state(_neo4j_query)
    return None if state == GRAPH_OK else graph_error(state, detail)
```

Правка одного `make_guard()` его не покроет, и пятый сервер останется с
четырёхсекундными вызовами. Это `B-1` внутри `B-1`: общая точка написана,
а один из двух потребителей её не использует. Сначала перевести
`query-builder` на `make_guard`, потом чинить.

**Оценка:** 2–3 часа с тестами. Чинить первым.

## B-2. Короткие таймауты — тоже только у справки

**Диагноз.** `FAIL-1` опустил таймауты `platform-help` до 4 и 2 секунд с
обоснованием: локальный контейнер в docker-сети либо отвечает за доли
секунды, либо не отвечает вовсе.

Обоснование целиком применимо к Neo4j, но там осталось `timeout=10`:

```
mcp-metadata-graph/server.py:   urlopen(req, timeout=10)
mcp-query-builder/server.py:    urlopen(req, timeout=10)
```

**Цена.** Наблюдаемые 3,85 с — это отказ TCP, а не срабатывание таймаута.
То есть сегодня десятка не мешает. Но при другом виде отказа — сеть есть,
Neo4j не отвечает — цена вызова станет десять секунд вместо четырёх, и
проявится это ровно тогда, когда хуже всего.

**Что делать.** Вынести в переменную окружения по образцу
`HELP_QDRANT_TIMEOUT_SEC`, поставить 4–5 секунд.

**Оценка:** полчаса, делается вместе с `B-1`.

## B-3. Печать, которая не может уронить вызов, — только у справки

**Диагноз.** `FAIL-2` завёл в `platform-help` функцию `_say()`: печать в
`try`, при отказе ASCII-приближение, при повторном — молчание. Поводом был
`UnicodeEncodeError` на знаке `⚠` в консоли cp1251.

Знаки `✓` и `⚠` печатают ещё семнадцать модулей. Для тех, что живут в
контейнерах, это неопасно — там UTF-8. Но **четыре скрипта запускаются на
хосте**: `check_prereqs.py`, `eval_all.py`, `run_all_tests.py`,
`probe_hbk.py`.

Проверено прямым запуском:

```
$ PYTHONIOENCODING=cp1251 python3 scripts/eval_all.py --summary-only
UnicodeEncodeError: 'charmap' codec can't encode character '\u26a0'
```

**Цена.** Сегодня спасает то, что консоль PowerShell переведена в UTF-8
руками, командой из инструкций. Стоит перенаправить вывод в файл, запустить
из CI или забыть две строки в начале сессии — и скрипт падает. Причём
`check_prereqs.py` — тот самый инструмент, к которому идут, когда что-то не
работает.

**Что делать.** Общий `_say()` уровня набора либо `sys.stdout.reconfigure`
в начале каждого хостового скрипта. Второе — три строки на файл и
надёжнее: покрывает и чужой код, который эти скрипты зовут.

**Оценка:** час.

---

## B-4. Три словаря пагинации вместо одного

**Диагноз.** `mcp_pagination.py` лежит в корне набора как общий модуль.
Пользуется им один сервер:

| Сервер | Чем отдаёт постраничность |
|---|---|
| `metadata-graph` | `mcp_pagination`: `total`, `returned`, `offset`, `limit`, `has_more`, `next_offset` |
| `bsl-checker` | своя реализация с тем же словарём |
| `query-builder` | `trim_fields_payload`: только `attributes_total` |
| `platform-help` | ничего, кроме `limit` |

**Цена.** Не столько дубликат кода, сколько отсутствие общего контракта.
Правила Cursor не могут сказать «если `has_more: true` — запроси
следующую страницу», потому что у двух серверов из четырёх такого поля
нет. Отдельно: `attributes_total` в `query-builder` — число, и предикатом
`path_non_empty` его не проверить (уже споткнулись на `qb-003` и `mg-404`).

**Что делать.** Свести к `mcp_pagination`; там, где постраничности нет по
существу, оставить как есть, но не изобретать третий словарь.

**Оценка:** полдня.

## B-5. Прогресс-лог долгих операций — только у индексера

**Диагноз.** `ProgressLogger` (`PERF-5`) применён в шести модулях, и все
шесть — индексер метаданных. Индексатор справки его не знает, хотя идёт
1 час 48 минут.

**Цена.** Меньше, чем кажется: `hbk_indexer` печатает построчно по каждому
контейнеру, немой он не бывает. Но процентов и ETA нет, и «сколько ещё
ждать» ответить нечем — ровно та жалоба, из-за которой появился `PERF-5`.

**Что делать.** Одна строка в цикле по контейнерам. Модуль придётся класть
в образ `Dockerfile.embeddings` — и это ещё один `COPY`, который забывают.

**Оценка:** час. Делать вместе с `PERF-6`, если за него возьмётесь.

## B-6. Контрактный тест по исходнику — только для Cypher

**Диагноз.** `tests_graph_contract.py` проверяет запросы к графу по тексту
файлов: метки узлов, имена свойств, каталоги серверов и индексера. Родился
из `PERF-4`, который повторился в другом файле просто потому, что тест
смотрел в один каталог.

Приём сильный и в этом заходе сработал ещё трижды — но каждый раз его
приходилось изобретать заново, в новом файле: `tests_shortfall` проверяет
`COPY` в двух Dockerfile, `tests_refusal` — в трёх, `tests_lockfile_pairs`
— два генератора, `tests_fail1_fast_fail` — длинные таймауты в исходнике.

**Цена.** Пять наборов делают одно и то же разными способами. Проверка
«модуль X импортируется сервером Y, значит `COPY` обязан быть в его
Dockerfile» написана дважды и оба раза со своим списком образов — то есть
сама является тем самым «списком, который надо помнить».

**Что делать.** Один набор `tests_delivery.py`: строит соответствие
«импортёр → образ» из исходников и Dockerfile автоматически, без списков
руками. Тогда следующий общий модуль защищён по факту появления.

**Оценка:** полдня. Ценность растёт с каждым новым общим модулем.

## B-7. Проверка живости бэкенда — у двух серверов из четырёх

**Диагноз.** У `metadata-graph` есть `graph_state`, у `platform-help` —
`_detect_help_collection_kind`. У `bsl-checker` и `query-builder` — ничего.

`query-builder` ходит в тот же Neo4j и пользуется чужим `graph_state`, так
что фактически прикрыт. А `bsl-checker` про свой бэкенд (java + jar
линтера) узнаёт только в момент запуска анализа: `FileNotFoundError` на
`java`, отсутствие jar, таймаут в 120 секунд.

**Цена.** Умеренная: `OBS-1` научил различать эти отказы, и модель теперь
получает честное «ответа нет». Но узнаёт она об этом через две минуты
ожидания, а `platform_help_stats` умеет отвечать про своё состояние сразу.
У `bsl-checker` инструмента «как ты себя чувствуешь» нет вовсе.

**Что делать.** `bsl_stats` по образцу двух других: версия jar, доступность
java, время последнего успешного анализа. Заодно закрывается несимметрия —
у трёх серверов из пяти такой инструмент есть, у двух нет.

**Оценка:** 2 часа.

## Чего в проекте НЕ нашлось

Отдельно стоит назвать то, что искал и не обнаружил, — отсутствие тоже
результат:

- **повторов с бэкоффом нет нигде.** Ни одного `for attempt in range(...)`.
  Это осознанно или случайно, но однообразно, и в текущем виде правильно:
  быстрый честный отказ лучше трёх молчаливых попыток;
- **метрики (`mcp_metrics`) собирает только `start.py`**, серверы их не
  пополняют. Возможная тема отдельного разбора;
- **фильтр инструментов (`mcp_tool_filter`) применяется только в `start.py`**
  — это правильно, там ему и место.

## Порядок работ

| Задача | Оценка | Почему в этом порядке |
|---|---|---|
| `B-1` быстрый отказ для Neo4j | 2–3 ч | самая большая цена, самый вызываемый сервер |
| `B-2` короткие таймауты | 0,5 ч | делается тем же движением |
| `B-3` безопасная печать в хостовых скриптах | 1 ч | дёшево, ломается у всех |
| `B-7` `bsl_stats` | 2 ч | закрывает несимметрию инструментов состояния |
| `B-6` общий тест доставки модулей | 4 ч | окупается со следующего общего модуля |
| `B-4` единый словарь пагинации | 4 ч | нужен для правил Cursor |
| `B-5` прогресс-лог индексатора справки | 1 ч | вместе с `PERF-6` |

Первые три — один заход на полдня, и он снимает самую заметную часть.

## Метод, а не вывод

Главное этого аудита — не семь пунктов, а способ их искать. Вопрос
«что уже сделано правильно в одном месте» дал за час семь находок, тогда
как `AUDIT-1` с вопросом «чего не хватает» дал десять за день. Разница в
том, что здесь не нужно придумывать решение: оно есть, обкатано и
задокументировано, остаётся перенести.

Проверять стоит после каждого захода, где что-то чинилось точечно. Признак
находки простой: правка, у которой в комментарии написано «ровно тот же
случай, что и в …», — кандидат на распространение, а не на копию.
