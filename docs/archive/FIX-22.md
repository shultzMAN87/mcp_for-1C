# FIX-22. Перенос документов упал посреди работы

Три файла в `scripts/`. Кладутся поверх, ничего больше не трогают.

---

## Что случилось

```
UnicodeDecodeError: 'charmap' codec can't decode byte 0x98
AttributeError: 'NoneType' object has no attribute 'strip'
```

Моя ошибка, и обидная: это `B-3` в третий раз, только с другой стороны
трубы.

`subprocess.run(..., text=True)` **без явной кодировки** декодирует вывод
тем, что вернёт `locale.getpreferredencoding()` — на русской Windows это
cp1251. Git на отказе печатает имя файла, а имена документов здесь
кириллические. Поток-читатель падает с `UnicodeDecodeError` **в отдельном
потоке**, `run()` этого не замечает и возвращает `stderr = None`, дальше
`.strip()` на `None` — и скрипт умирает посреди переноса.

Проект дважды чинил эту болезнь для СВОЕГО вывода: `_say()` в сервере
справки и `PYTHONIOENCODING` дочерним процессам в `run_all_tests.py`.
`tests_host_scripts.py` проверял ровно это — что скрипт настраивает свои
потоки. Про чтение чужого вывода не спрашивал никто.

Два урока, и второй важнее:

- кодировку при чтении вывода надо задавать явно, **всегда**;
- `errors="replace"` обязателен. Диагностика печатается ради операции, а не
  наоборот; строгий режим превратил нечитаемое сообщение в отказ всей
  команды.

## Что ещё нашлось

**Тест против всего класса** (а не против одного места — болезнь не в
скрипте, а в привычке писать `text=True`) сразу указал на ещё два вызова в
`check_prereqs.py`. Скрипт, к которому приходят именно тогда, когда что-то
не работает, — то есть ровно тогда, когда docker печатает необычные
сообщения. Починены.

**Второй дефект, нашёлся при проверке починки.** Под ASCII-локалью скрипт
не узнал `СТАТУС.md` и унёс его в архив — молча, отрапортовав «остаётся в
корне: 6». Причина та же семья: если Python читает каталог не в UTF-8,
кириллическое имя с диска не совпадает со строкой в списке канона.

Теперь скрипт сверяет кодировку файловой системы **до** первого движения и
отказывается работать, если она не UTF-8. Перенос пятидесяти файлов одной
командой слишком необратим, чтобы угадывать.

**Мелочь, но раздражающая:** первая строка обещала 56 файлов, последняя
рапортовала про 55, и приходилось гадать, потерялся файл или так задумано.
Теперь пропускаемые называются явно.

## Что НЕ ошибка

`fatal: not under version control` на `README-DOC-2.md`,
`README-PERF-6-1.md`, `README-ЗАХОД-6.md` — эти документы приезжали
архивами и под контроль версий не попадали. Скрипт двигает их обычным
переименованием; для неотслеживаемого файла разницы нет. Сообщение стало
внятным: `(не под контролем версий)` вместо куска чужого стека.

`пропуск PLAN.md — в архиве уже есть` — так и задумано, см. шаг 3.

## Как продолжить

Скрипт идемпотентен: уже перенесённое он пропускает. Доводить начатое до
конца — просто запустить заново.

```powershell
cd D:\Docker\30_mcp_cursor

# 1. Положить три файла из этого архива поверх scripts/

# 2. Досчитать перенос — остановился на ИТОГИ-ЗАХОДА-5-2.md
python scripts\archive_docs.py --dry-run
python scripts\archive_docs.py

# 3. Корневой PLAN.md (копия в архиве — тот же файл плюс шапка DOC-5)
git rm -f PLAN.md

# 4. Указатель
python scripts\gen_archive_index.py

# 5. Проверить
python scripts\run_all_tests.py --strict
```

Ожидается **35 наборов, 1016 тестов** (было 1014 — два новых теста на
декодирование).

В корне должно остаться ровно пять `.md`: `README.md`, `ARCHITECTURE.md`,
`PROMPTS.md`, `СТАТУС.md`, `PLAN-6.md`. Если `tests_docs_canon.py` ругается
— скажите, что именно он пишет.
