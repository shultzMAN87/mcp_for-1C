# ITS-1: удаление мёртвой ветки ИТС из platform-help

Заход по `PLAN-5`, блок B. Дата: 15 августа 2026.

Единственная необратимая правка набора: она не добавляет, а удаляет
работающий (хоть и отключённый) код. Возврат — только через git.

---

## Что удалено

Из `mcp-platform-help/server.py` — **297 строк**, 1164 → 867:

- инструменты `its_search` и `search_all`;
- внутренняя механика ИТС: `_its_search_hybrid`, `_its_search_legacy_dense`,
  `_detect_its_collection_kind`, форматирование результатов ИТС;
- переменная `ITS_COLLECTION`;
- поля `its_collection`, `its_points`, `its_collection_kind`,
  `its_search_mode` из `platform_help_stats`.

Из `mcp_tool_filter.py` — список `NO_DATA` стал пустым: обе записи в нём
относились к удалённым инструментам. Сам механизм фильтра остался, следующий
инструмент без данных пропишется туда же.

Из `docker-compose.yml` — строка `ITS_COLLECTION=its_articles` в сервисе
`mcp-platform-help`.

Осталось пять инструментов: `platform_help_search`, `platform_help_lookup`,
`platform_help_details`, `platform_help_kinds`, `platform_help_stats`.

## Почему это не копирование файлов, как планировалось

Подготовленная ветка `optional-ubrat-its/` снята с версии `server.py` от
**10 августа**. После этого тот же файл менялся под HBK-1: добавлен импорт
`help_ranking` и переработан `_help_search` (добор кандидатов + прореживание
выдачи).

Копирование поверх, как предполагала инструкция ветки, **затёрло бы правку
ранжирования**: `ph-002` снова упал бы, а сервер, скорее всего, не поднялся
бы вовсе — `Dockerfile.embeddings` копирует `help_ranking.py`, который никто
уже не импортирует, и падение случилось бы не на старте, а тише.

Поэтому сделано слияние: за основу взят файл из ветки, поверх наложены две
правки HBK-1 по точным якорям (совпадение проверялось на единственность).

## Как проверялось, что ничего не сломано

1. **Синтаксис** — `py_compile` на слитом файле.
2. **Мои правки на месте** — `diversify_hits` и `help_ranking` присутствуют;
   diff «слитое против текущего» не содержит ни одной строки с ними, то есть
   удаляется только код ИТС.
3. **Висячих ссылок нет** — разбор AST: все вызываемые имена определены или
   импортированы; `ITS_COLLECTION` не упоминается нигде в коде (три
   оставшихся совпадения — в докстринге, который объясняет удаление).
4. **Внешних потребителей нет** — поиск `its_search|search_all|_its_` по
   всему набору, `docker-compose.yml` и `.cursor/rules/`: реальных
   совпадений не осталось (те, что находятся в тестах, — английское слово
   «its» в именах тестовых методов).
5. **Compose валиден** — 12 сервисов, у `mcp-platform-help` 7 переменных
   окружения без ИТС, `depends_on` только на `qdrant`.
6. **Тесты** — 17 наборов, 696 тестов, 0 провалов.

## Приёмка

```powershell
python scripts\run_all_tests.py
docker compose build mcp-platform-help
docker compose up -d --force-recreate mcp-platform-help
python scripts\eval.py --dataset evals/datasets/platform_help.jsonl
```

Ожидается 13/13 hard, MRR 0.845 — то же, что до этой правки: удаление ИТС
поиска по справке не касается. Если числа изменились — значит, слияние
задело `_help_search`, и это повод откатить.

Дополнительно стоит глазами: `platform_help_stats` в Cursor не должен
содержать полей `its_*`, а список инструментов сервера — показывать пять
штук.

**Откат:** `git revert` коммита. Файлы до правки — в `optional-ubrat-its/`
ветка (версия без ранжирования) и в истории git (версия с ранжированием и
ИТС).
