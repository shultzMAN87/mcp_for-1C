# Заходы 11–12 — граф следит за выгрузкой через git и собирается за минуты

Планы — `PLAN-11.md` и `PLAN-12.md` (оба здесь же, в архиве), раздел
«Как реализовано» в конце `PLAN-12.md` — таблица задач с местами в коде.
Принято на стенде 3–4 ноября 2026.

## Что было

- Граф узнавал об изменениях выгрузки обходом 56 тысяч файлов через
  границу Docker Desktop: 3–12 минут на каждое «а что поменялось».
- Полная индексация шла 2,5 часа, из них 2,2 часа — фикс-пойнт резолва.
- Watcher был выключен: опрос файлов на этом масштабе стоил столько же,
  сколько явное обновление.

## Заход 11 (`SRC`): источник правды — git

Граф помнит коммит, по которому собран (`indexed_sha`), и файлы, которые
агент правил поверх него (`dirty`). Одна функция `source_sync.sync()`
догоняет граф для всех: индексер при старте, watcher по таймеру,
`graph-refresh.ps1` вручную, `metadata_refresh` из чата. Порядок между
ними держит аренда записи в Neo4j. Git в контейнере только читает
(белый список подкоманд).

На стенде: переход прошёл, git в контейнере работает на bind-mount с
Windows, `graph-refresh.ps1 -DryRun` отвечает за 0,1 с.

## Заход 12: полная индексация 2,5 ч → 8,5 мин

| Что | Чем |
|---|---|
| квадратичный поиск дублей callsite | `PERF-17`: `any(...)` по всем callsite'ам прохода на каждый вызов менеджера → множество. Итерация 45+ мин → 2,8 мин в один процесс |
| одно ядро из двенадцати | `PERF-15`: разбор и резолв в 4 процессах (fork), сборка в исходном порядке. Итерация 2,8 мин → 53 с; результат совпал с однопроцессным до единицы |
| второй обход выгрузки | `PERF-14`: список `.bsl` из `git ls-files` |
| ~2 600 модулей мимо графа | `FIX-34`: наборы записей, команды, модули конфигурации, общие формы и команды, HTTP- и веб-сервисы |
| код молча пропадал из разбора | `FIX-36`/`37`/`38`: кавычка в комментарии съедала код до следующей кавычки; `…; КонецПроцедуры` на одной строке; `//`-строки внутри текста запроса. На одном модуле старый разбор видел 33 процедуры из 98 |
| две индексации писали в граф разом | `FIX-39`: у всех индексеров было одно имя владельца аренды; теперь `indexer:<контейнер>:<pid>`, аренда 30 мин с продлением |
| `graph-refresh.ps1 \| Tee-Object` обрывал скрипт | `FIX-40`: скрипт сам пишет лог в `logs\` |
| 68 процедур без владельца | `FIX-41`: шесть форм лежат на диске, но не числятся в XML объектов — отсеиваются с причиной |
| CI красный с 1 сентября | `CI-6`: workflow не ставил PyYAML для проверок документации |

Гипотеза «виноват сборщик мусора» проверена замером и отвергнута: 11 с
на весь резолв. Блок C плана (PyPy, профилирование) не понадобился.

## Уроки

- Падение скорости внутри одной итерации при том же числе вызовов на
  процедуру — признак квадратичного роста, а не тяжёлых модулей. Нашлось
  по логу прогресса, а не профилем.
- Предупреждение «декларация без конца» было верхушкой: на каждое такое
  место приходились десятки молча потерянных процедур. Предупреждение
  парсера стоит разбирать по месту, а не считать.
- Инструкция «запустите с `| Tee-Object`» в Windows PowerShell 5.1 с
  `$ErrorActionPreference = "Stop"` обрывает скрипт на первой строке
  stderr. Логи должен писать сам скрипт.
