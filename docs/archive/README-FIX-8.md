# `FIX-8` — восемь неразбираемых видов объектов

Последняя задача Блока B (`PLAN-4.md` §3). Блок закрыт.

**Требуется переиндексация слоя 1** — меняется состав объектов в графе:

```powershell
docker compose build metadata-indexer mcp-metadata-graph mcp-query-builder workspace-watcher
$env:METADATA_FORCE_XML="true"
docker compose up -d --force-recreate metadata-indexer
docker logs -f metadata-indexer
$env:METADATA_FORCE_XML="false"
```

`METADATA_FORCE_XML` тянет за собой и фазу 2 — очистка слоя 1 сносит
`:Module`-узлы. То есть это полный прогон, около двух часов. Заодно
`ensure_schema` создаст полнотекстовые индексы из `PERF-6`, если вы их ещё
не создали вручную.

## Что было

Парсер знал 35 видов из 43, встреченных в вашей конфигурации. Не
разбирались: `Sequences`, `ExternalDataSources`, `DocumentNumerators`,
`CommandGroups`, `StyleItems`, `Styles`, `WSReferences`, `XDTOPackages`.

Следствия двух родов.

**Видимое** — 156 неразрешённых ссылок при сборке графа. В логе они
выглядели так:

```
WARNING   CONTAINS→StyleItem.ТекстЗапрещеннойЯчейкиЦвет: 1
WARNING   CONTAINS→XDTOPackage.Пакет_dnsFactory: 1
```

Подсистемы и другие объекты ссылались на цели, которых в графе не было.

**Важное** — `Последовательность` и `ВнешнийИсточникДанных` есть в языке
запросов: `TABLE_PREFIXES` в `query_parser` их знает. Но объектов в графе не
существовало, и `query_validate` отвечал «таблица не найдена» на
**корректный** запрос. Это хуже пропуска: агент по такому ответу перепишет
верный запрос на неверный.

## Что стало

Все восемь видов добавлены в таблицу `KINDS`. Разбор общий:
`_parse_object` читает `Properties`/`ChildObjects` и от вида не зависит —
поэтому у последовательностей сразу появляются измерения, а у остальных
узел с именем и синонимом, чего достаточно для разрешения ссылок и поиска.

## Известное ограничение

У `ВнешнийИсточникДанных` таблицы лежат во вложенных каталогах
(`Tables/*.xml`), а `walk_workspace` намеренно не заходит в подкаталоги —
формы и макеты уже описаны в верхнем XML.

Значит: узел источника появится, ссылки разрешатся, `query_validate`
перестанет браковать запрос — но **проверить имена полей внешней таблицы
по-прежнему не сможет**. Это честнее, чем не иметь узла вовсе, и меньше,
чем полная поддержка. Доделывать стоит по факту потребности, а не заранее.

Ограничение зафиксировано тестом `test_external_data_source_tables_not_parsed`
— он упадёт, если однажды его снимут, и тогда этот раздел надо будет
переписать.

## Что проверить после прогона

**1. Неразрешённых ссылок должно стать заметно меньше 156.** Строка
«Неразрешённых ссылок: N» идёт сразу после «Собираем граф». Полного нуля
не ждите: часть ссылок ведёт на объекты по UUID, которых в выгрузке
действительно нет.

**2. Новые виды в графе:**

```powershell
@'
MATCH (n:MetadataObject) WHERE n.kind_eng IN
  ['Sequence','ExternalDataSource','XDTOPackage','StyleItem','Style',
   'CommandGroup','WSReference','DocumentNumerator']
RETURN n.kind_eng AS kind, count(*) AS n ORDER BY n DESC;
'@ | docker exec -i neo4j cypher-shell -u neo4j -p $pw
```

По вашим прежним счётчикам ожидаются как минимум `StyleItem` и
`XDTOPackage`; остальные — сколько есть в конфигурации.

**3. Главное — `query_validate` на последовательности.** Если в
конфигурации есть последовательность, попросите в Cursor проверить запрос
вида `ВЫБРАТЬ * ИЗ Последовательность.<Имя>`. До этого патча ответ был
«таблица не найдена».

## Тесты

`tests_fix8_kinds.py` — 9 тестов, офлайн. Всего 546.

Отдельно проверяется, что в таблице `KINDS` нет дублей ни по каталогу, ни
по `kind_eng`, ни по `kind_ru`: дубль означал бы, что один каталог
разбирается дважды и объекты попадают в граф по два раза.
