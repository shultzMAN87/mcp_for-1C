# LOCK-1: лок-файл для образа v8std

Заход по `PLAN-5`, блок B. Дата: 15 августа 2026.

## Почему задача висела

Не потому, что до неё не дошли руки. Два скрипта, делающих одно и то же,
разошлись:

| | `scripts/gen_lockfiles.sh` | `scripts/gen_lockfiles.ps1` |
|---|---|---|
| base | есть | есть |
| bsl | есть | есть |
| embeddings | есть | есть |
| **v8std** | **есть** (строка 35) | **не было** |

На Linux `make lock` генерировал четыре лок-файла, на Windows — три.
Разницы не видно ниоткуда: скрипт отрабатывает успешно, пишет «Готово» и
перечисляет то, что сделал, — а чего он не сделал, не говорит никто. Ещё
один случай «отказ выглядит как успех», только на этот раз в инструментах.

Правка: в `gen_lockfiles.ps1` добавлена пара `v8std` и значение `v8std` в
`ValidateSet` параметра `-Only`. Файл сохранён в **UTF-8 с BOM** и с
LF-переводами строк — как оригинал; PowerShell 5.1 без BOM читает `.ps1`
как cp1251 и ломается на кириллице.

---

## Что делать

### 1. Заменить скрипт

`scripts/gen_lockfiles.ps1` из архива — поверх существующего.

### 2. Сгенерировать лок

```powershell
.\scripts\gen_lockfiles.ps1 -Only v8std
```

Если PowerShell откажется из-за политики выполнения:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\gen_lockfiles.ps1 -Only v8std
```

Нужна сеть: резолв идёт внутри `python:3.12-slim` (та же база, что в
`Dockerfile.v8std`), а не локальным pip — набор версий зависит от версии
Python и платформы.

Ожидаемый вывод — строка `→ requirements-v8std.txt → requirements-v8std.lock.txt
(в python:3.12-slim)` и в конце `requirements-v8std.lock.txt  пакетов: N`.

### 3. Проверить, что получилось

```powershell
type 1c-mcp-suite\requirements-v8std.lock.txt
```

Что должно быть:

- `mcp==1.27.0` — версия зафиксирована точкой в исходных требованиях, и
  ослаблять пин нельзя: сервер чужой, а SDK ломает совместимость между
  минорными версиями. Если в локе оказалась другая версия — это ошибка,
  не собирайте образ.
- `pyyaml==6.x` — граница `>=6.0,<7`.
- Транзитивные зависимости `mcp` (их около десятка: `anyio`, `httpx`,
  `pydantic`, `starlette`, `uvicorn` и прочие) — с точными версиями.
- Пакетов должно быть **заметно больше двух**. Если ровно две строки —
  `pip-compile` не отработал, а записал вход как выход.

### 4. Пересобрать образ

```powershell
docker compose build v8std-mcp
```

В логе сборки нужна строка:

```
TR-2: ставим из requirements-v8std.lock.txt
```

Если вместо неё `TR-2: requirements-v8std.lock.txt пуст — ставим по
границам` — значит лок не заполнился, и шаг 2 надо разобрать, а не
пропускать.

### 5. Убедиться, что сервер живой

```powershell
docker compose up -d v8std-mcp
docker compose ps v8std-mcp
python scripts\eval.py --dataset evals/datasets/v8std.jsonl
```

Последняя команда — главная проверка: она поднимает сервер и гоняет по нему
реальные запросы. Числа сравните с прошлым отчётом:

```powershell
dir evals\reports\v8std_*.md
```

Последний прогон был 10 августа. Результат после пересборки должен
совпасть: лок-файл фиксирует версии, а не меняет их — если что-то
изменилось, значит `pip-compile` подобрал версии, отличные от тех, что
стояли в образе до сих пор, и это стоит увидеть до, а не после.

---

## Чем это ценно

Пока лока нет, любая пересборка `v8std-mcp` может дать другой набор версий
— в том числе через полгода, когда `mcp` выпустит новую минорную и
транзитивные зависимости уедут. Образ, который сегодня собирается, завтра
может не собраться, и причина будет не в вашем коде.

Три остальных образа этим уже защищены. Этот был последним незакрытым.

## Заодно

Проверьте, что `gen_lockfiles.sh` и `.ps1` больше не расходятся ничем,
кроме языка. Разошлись они молча — значит, разойдутся снова. Хорошая
страховка: тест, который парсит оба файла и сверяет списки пар. Это уже
находка `A-2` из `AUDIT-1` в другой одежде — вход против выхода, только
здесь входы это два списка, которые обязаны совпадать.
