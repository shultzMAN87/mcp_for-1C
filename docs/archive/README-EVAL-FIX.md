# `EVAL-1` — три мои ошибки, найденные первым прогоном

Прогон дал 3 из 16. Ни одна неудача не была дефектом инструментов —
все три причины мои.

```powershell
docker compose --profile evals build eval-runner
python scripts\eval.py --dataset evals/datasets/metadata_graph.jsonl
```

**Пересборка `eval-runner` обязательна.** Его `predicates.py` копируется в
образ, а вы пересобирали четыре других — поэтому мой фикс из прошлого
патча в прогон не попал.

---

## 1. Четыре «ошибки транспорта» — инструментов нет в профиле

`metadata_object_details`, `metadata_list_kinds`, `metadata_subsystems`
убраны фильтром `mcp_tool_filter.py` как дубли:

| Убран | Чем заменён |
|---|---|
| `metadata_object_details` | `metadata_object_attributes` |
| `metadata_subsystems` | `metadata_subsystem_tree` |
| `metadata_list_kinds` | `metadata_stats`, секция `by_kind` |

Вызов несуществующего инструмента возвращает не JSON — отсюда
`json decode: Expecting value`.

Я писал датасет по коду серверов, ни разу не сверившись с тем, какие
инструменты реально доступны агенту. При том что в проекте для этого есть
`scripts/list_tools.py`.

Датасет переписан на канонический набор.

## 2. Пять поисков — раннер не знал ключей ответа

`predicates._hits` искал список найденного в `results`. В прошлом патче я
добавил `items`, но и этого мало: разные инструменты называют список
по-своему — `callers`, `callees`, `direct_attributes`.

Предполагать единое имя было наивно, а проверить надо было **до** того,
как писать датасет. Иначе провал раннера неотличим от провала
инструментов — что на первом прогоне и произошло: выглядело как сломанный
поиск.

## 3. `metadata_stats` — выдуманные пути

Я ожидал ключи `nodes` и `edges`. В ответе их нет: есть `metadata.objects`,
`metadata.by_kind`, `code.callables`. Пути выверены по реальному ответу.

---

## Чего ждать от следующего прогона

Не жду зелёного с первого раза. Оставшиеся расхождения будут двух родов, и
различать их важно:

* **ожидание неверно** — например, `mg-202` требует «НаименованиеПолное» в
  первых 20 реквизитах, а порядок в ответе другой. Правится в датасете;
* **инструмент отвечает неверно** — вот это и есть цель.

Три примера-ловушки (`mg-101`, `mg-103`, `mg-403`) прошли с первого раза —
это уже кое-что: инструменты не выдумывают ответ там, где данных нет, и
объясняют пустоту в границах подсистемы.

Присылайте отчёт — разберём построчно, где неправ я, а где граф.
