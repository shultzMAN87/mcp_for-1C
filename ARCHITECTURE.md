## Задача

AI-агент неплохо знает язык 1С и ничего не знает про **вашу** конфигурацию:
какие в ней объекты, кто кого вызывает, чем заполняется структура-параметр,
какими реквизитами документ связан со справочником. Спросить об этом негде,
поэтому агент правдоподобно выдумывает — и выдумывает тем увереннее, чем
конкретнее вопрос.

Набор закрывает эту дыру: пять MCP-серверов, каждый со своим источником
данных, отвечают на вопросы про конкретную конфигурацию, про синтаксис
платформы и про стандарты разработки.

Это инструмент для разработчика 1С, работающего с агентом (Cursor,
OpenCode, своё расширение для EDT), а не сервис и не библиотека.

## Карта

```
   выгрузка 1С (XML+BSL)     .hbk справки          github: zeegin/v8std
            │                      │                        │
            ▼                      ▼                        ▼
    metadata-indexer         help-indexer             fetch_v8std.py
            │                      │                        │
            ▼                      ▼                        ▼
       ┌─────────┐            ┌────────┐              ┌───────────┐
       │  Neo4j  │            │ Qdrant │              │ v8std-data│
       └─────────┘            └────────┘              └───────────┘
         │      │                  │                        │
         ▼      ▼                  ▼                        ▼
  metadata-  query-          platform-help              v8std-mcp
   graph     builder            :8003                     :8765
   :8001      :8009                                    (чужой сервер)
   :8002 bsl-checker — без хранилища, обёртка над BSL Language Server

              все пятеро: Streamable HTTP, /mcp, stateless
                                  │
                                  ▼
                            агент (Cursor)
```

Индексаторы — отдельные контейнеры и работают в одну сторону: серверы
только читают. Из-за этого сервер можно перезапускать когда угодно, а
переиндексация не мешает отвечать на вопросы (ответ станет хуже, и он сам
об этом скажет — см. `degraded` ниже).

## Пять серверов

| Сервер | Источник | Отвечает на вопрос |
|---|---|---|
| `metadata-graph` | Neo4j | что есть в конфигурации и кто кого зовёт |
| `bsl-checker` | BSL Language Server | что не так с этим кодом |
| `platform-help` | Qdrant | как это устроено в платформе |
| `query-builder` | Neo4j (только слой метаданных) | как написать корректный запрос |
| `v8std-mcp` | корпус v8std | что говорят стандарты разработки |

Граф двухслойный. **Слой 1** — метаданные из XML: объекты, реквизиты,
ссылки, подсистемы. **Слой 2** — код из BSL: процедуры, вызовы, работа с
объектами. Разделение не косметическое: слой 1 строится за минуты и его
достаточно для `query-builder`, слой 2 — самое долгое во всей индексации.

Разрешение вызовов в слое 2 идёт до неподвижной точки: вывод типов
параметров даёт новые связи, новые связи дают новые типы. Итерации
останавливаются по приросту результата, а не по счётчику.

## Пять решений, которые определяют остальное

**Серверы независимы.** Ни один не ходит в другой. Поэтому любой можно
выключить, заменить или подключить к другому агенту отдельно, а падение
одного не роняет остальные. Цена — нет инструмента, который объединял бы
выдачу разных источников: скоры несопоставимы, а межпроцессный вызов
между MCP-серверами сломал бы независимость.

**Транспорт один и без состояния.** Streamable HTTP, эндпоинт `/mcp`,
stateless. Ни SSE, ни stdio. Отсюда следствие, которое видно в API: хранить
состояние между вызовами негде, поэтому всё, что похоже на настройку,
передаётся параметром вызова или переменной окружения.

**Отказ обязан выглядеть отказом.** Проект четыре захода подряд ловил один
и тот же класс дефектов: пустой результат неотличим от ошибки. «Ошибок не
найдено» при незапустившемся анализаторе, «объект не найден» при пустом
графе, «поиск недоступен» при живом Qdrant. Поэтому в каждом ответе своих
серверов есть `answerable` (можно ли на ответ опереться) и `degraded`
(ответ пригоден, но хуже штатного), а индексаторы сверяют «вход против
выхода» (`shortfall.py`) и жалуются на недостачу сами.

**Чужое не переписываем.** Стандарты разработки отдаёт чужой сервер
(`zeegin/v8std`, CC0) — свой индекс был бы худшим дубликатом и разошёлся бы
с корпусом на первом обновлении. Анализ BSL — чужой BSL Language Server.
Своего кода ровно столько, сколько нужно, чтобы связать это с конкретной
конфигурацией.

**Проверка на соответствии, а не по перечню.** Списки, которые ведут
руками, отстают молча — в этом проекте они расходились четырежды. Поэтому
проверки строятся на сверке источника с источником: запросы серверов против
схемы, которую объявляет писатель графа (`tests_graph_contract.py`);
импорты модулей против строк `COPY` в Dockerfile (`tests_delivery.py`);
хостовые скрипты находятся по факту наличия файла.

## Чего в наборе нет

- **RAG по ИТС.** Лицензия и контент за авторизацией. Контекст по
  стандартам берётся из открытого корпуса.
- **Инструментов «на всякий случай».** Каждый новый инструмент — ещё одно
  место, где отказ может выглядеть успехом. Состав режется профилем
  (`mcp_tool_filter.py`).
- **Записи в конфигурацию.** Набор только читает. Правки пишет разработчик.

Свой код — MIT, см. [LICENSE](LICENSE). Дальше про чужое; это не
юридическая консультация, а карта того, откуда что берётся.

| Что | Лицензия | Как попадает к вам |
|---|---|---|
| BSL Language Server | LGPL-3.0 | jar скачивается при сборке образа с релизов `1c-syntax` |
| корпус v8std и его сервер | CC0 | `scripts/fetch_v8std.py`, в git не хранится |
| Neo4j Community | GPL-3.0 | официальный образ, отдельный процесс, общение по Bolt |
| Qdrant | Apache-2.0 | официальный образ |
| `sentence-transformers`, `fastembed` | Apache-2.0 | pip при сборке |
| модель `multilingual-e5-base` | MIT | скачивается при сборке образа |
| `torch` | BSD-3-Clause | pip при сборке |
| MCP Python SDK | MIT | pip при сборке |

**Справка платформы (`.hbk`) — проприетарные файлы 1С.** В репозитории их
нет и быть не может: вы берёте их из `bin\conf` своей установленной
платформы. То же со выгрузкой конфигурации — это ваш код, а не наш.

В репозитории не хранится ни одного чужого бинарника: всё чужое приезжает
при сборке образов или отдельным скриптом.

Проверить, что перед публикацией наружу не уедет лишнее:

```powershell
python scripts/check_publish.py
```
