# Итоги: стандарты разработки в наборе

Дата: 9 августа 2026. По `PLAN-STD.md`, с существенным отклонением от него.

Короткая версия: **половина плана не выполнена, потому что выполнять её не
надо было.** Пункт 0 плана — «полчаса посмотреть на MCP от v8std.ru» — дал
ровно тот результат, которого план допускал: задача закрывается чужими
руками, и лучше, чем предполагалось.

---

## 1. Что выяснилось на шаге 0

Разобрал исходники их сервера (`scripts/v8std_mcp_server.py`,
`v8std_mcp_index.py` в репозитории `zeegin/v8std`), а не только страницу с
описанием. Сопоставление с тем, что собирались писать:

| Инструмент v8std | Что делает | Задача из PLAN-STD |
|---|---|---|
| `v8std_search` | exact + BM25 + семантика, фильтр по типам, понимает `std437` | `STD-4.1` `std_search` |
| `v8std_get_page` | точная выдача по id / алиасу / URL, чистый Markdown | `STD-4.2` `std_get` |
| `v8std_explain_diagnostics` | список кодов ACC / BSLLS / EDT → диагностики, сгруппированные со связанными пунктами | `STD-4.3` `std_for_diagnostic` |
| `v8std_get_related` | переходы стандарт ↔ диагностика ↔ стандарт | в плане не было |
| `v8std_explain_snippet` | подбор стандартов по фрагменту BSL / SDBL | в плане не было |

Плюс MCP-ресурсы `llms.txt`, `llms-full.txt`, `pages.jsonl`.

Отдельно нашлась вещь, которой в плане не было вовсе: **локальный запуск**
(`v8std.ru/support/#local-mcp`, порт 8765). Он снимает оба возражения
против чужого сервера, сформулированных в §2 плана:

- `v8std_explain_snippet` отправляет фрагмент кода — на публичный сервис
  закрытый код слать нельзя, авторы пишут это прямым текстом;
- требование независимости и работы без интернета соблюдается буквально:
  это отдельный контейнер со своим `/mcp`, подключаемый к любому агенту.

**Вывод.** `STD-2` (парсер + чанкер, оценка «день») и `STD-3` (индексатор,
«полдня») отменены. Свой индекс был бы строго худшим дубликатом чужого
сопровождаемого — и начал бы расходиться с корпусом на первом же `git
pull`, которого никто не сделает. Это ровно тот риск «актуальности», что
описан в §6 плана; лучший способ его закрыть — не заводить второй источник.

Заодно отпало главное архитектурное решение плана (§3, «единица индексации
— пункт, а не документ»). Оно было правильным для своего индекса, но чужой
уже нарезан по-своему, и переспорить его нечем — да и незачем.

## 2. Что сломало наивный план забора корпуса

`STD-1` предполагал `git clone` репозитория. Так не работает: **каталог
`docs/ai/` у них в `.gitignore`**. Клон даёт markdown-корпус, но не даёт
`pages.jsonl` и `search-vectors.jsonl` — а это и есть индекс, который
читает сервер. Собрать их из клона можно, но генераторы тянут Pillow,
PyYAML, zensical и внутреннюю раскладку их скриптов — весь чужой тулчейн
ради двух файлов, которые автор публикует уже собранными.

Поэтому `scripts/fetch_v8std.py` качает ровно то, что нужно для запуска:
два артефакта индекса с сайта, пять python-модулей сервера и
`retrieval-rules.yml` из репозитория. Git на хосте не нужен, сеть нужна
один раз. Версия фиксируется в `v8std-data/FETCH.json`: ref, коммит, дата,
sha256 и размер каждого файла — это ответ на риск «актуальность» из §6,
теперь на вопрос «насколько индекс отстал» отвечает
`fetch_v8std.py --check`.

## 3. Что сделано

### `STD-1` — забор корпуса ✔ (переопределена)

`scripts/fetch_v8std.py`, каталог `./v8std-data` в `.gitignore`,
`make v8std` и `make v8std-check`.

### `STD-2`, `STD-3` — отменены

Обоснование выше. Полтора дня работы не потрачены.

### `STD-4` — сервер и подключение ✔ (иначе, чем в плане)

Вместо четырёх инструментов внутри `platform-help` — пятый сервер набора:

- `1c-mcp-suite/Dockerfile.v8std` — только среда: `mcp==1.27.0` + PyYAML.
  Чужой код в образ **не копируется**, он монтируется из `./v8std-data:ro`.
  Так обновление корпуса и обновление сервера — одна операция, чужой код не
  попадает в наш git и не превращается в форк, который однажды начнут
  править. Тот же приём, что с `platform-help-data/*.hbk`;
- `1c-mcp-suite/v8std_entrypoint.py` — свой только запуск: флаги
  `--allowed-host` (аналог `TR-4`), понятная диагностика вместо чужого
  traceback, режим «нет корпуса → взять индекс с сайта» с возможностью
  запретить его (`V8STD_ALLOW_REMOTE_INDEX=0` → выход 78, как у остальных
  серверов при плохой конфигурации);
- сервис `v8std-mcp` в `docker-compose.yml`: порт только на `127.0.0.1`,
  `cap_drop: ALL`, healthcheck на `/healthz` (он у них отдаёт 503, пока
  индекс не загружен, — то есть проверяются данные, а не только процесс),
  том `v8std-cache` под кеш;
- подключение: `.cursor/mcp.json`, `mcp-config.json`,
  `mcp-config-localhost.json`, `scripts/list_tools.py`.

**Про авторизацию.** Bearer из `mcp_auth.py` — наша схема, чужой сервер про
неё не знает, и это единственный сервер набора без токена. Компенсация та
же, что у Neo4j и Qdrant: публикация только на loopback. Считать это
«дырой» не стоит, но и не заметить нельзя — поэтому написано и здесь, и в
README, и в комментарии к сервису.

### `STD-5` — связка с bsl-checker ✔ (проще, чем в плане)

План предлагал положить `diagnostic-standard-links.json` (305 связей) в
образ `Dockerfile.bsl`. Не понадобилось: `v8std_explain_diagnostics`
разрешает коды сам, по свежему корпусу, принимает **список** и группирует
результат по стандартам. Копия карты в образе устаревала бы молча.

Сделано: `bsl_check_*` добавляет к каждой диагностике `std_ref`
(`bslls:UsingModalWindows`) и секцию `std_lookup` с уникальными кодами и
подсказкой. Ни сети, ни данных у сервера по-прежнему нет — независимость
сохранена, а агент получает то, чего не хватало: не «нарушено правило
UsingModalWindows», а «нарушен std703, вот требование».

В `bsl_check_directory` коды собираются по всем файлам, а не по странице
пагинации, — иначе список стандартов зависел бы от запрошенного `offset`.

### `STD-6` — датасет и сокращение правил ✔

- `evals/datasets/v8std.jsonl` — 15 примеров: точная выдача по номеру,
  поиск формулировкой, мост от кодов линтера, переходы по связям, подбор по
  сниппету и **две ловушки** (несуществующий `std999`, несуществующий код
  диагностики). Правило `PLAN-4 §EVAL-1` — «нет измерения, нет новой
  функциональности» — не нарушено;
- `evals/runner/predicates.py` — два новых предиката, `field_equals` и
  `path_non_empty`, по точечному пути в ответе. Понадобились потому, что у
  `v8std_get_page` и `v8std_explain_diagnostics` нет ключа `results`, на
  который смотрит `_hits()`. Плюс `name_in_top_k` теперь заглядывает в `id`
  и `title` — у v8std опознавательный признак хита именно там. Старые
  датасеты ведут себя как раньше: у `platform_help` этих ключей в хите нет;
- `scripts/eval.py` — выбор сервера (`--server`, автоопределение по имени
  датасета). Раньше адрес был захардкожен;
- `.cursor/rules/bsl-code.mdc` **переписан**: вместо пересказа стандартов —
  формулировка плюс номер. Единственное место, где добавка к стандарту
  осталась осознанно, — `Выполнить()`: помимо std770 там сказано, что такой
  вызов не попадает в граф вызовов и `code_callers` его не покажет. Это
  факт про наш инструмент, в стандарте его нет и быть не может;
- `.cursor/rules/mcp-tools.mdc` — пятый сервер, порядок вызовов, таблица
  «три источника — три разных вопроса» и предупреждение про авторские
  комментарии (в v8std они помечены цитатой «В стандарте не указано»; это
  практика, а не норма вендора, и в код-ревью путать их вредно).

## 4. Что осталось нерешённым

**Опциональный набор `optional-ubrat-its/`.** Мёртвая ветка ИТС в
`platform-help` (~300 строк, коллекция `its_articles`, `search_all` с
докстрингом, не соответствующим коду). `DATA-1` закрыта, но не наполнением
этой коллекции, а отдельным сервером, — значит, код мёртв по построению.
Вынесено отдельно: это единственная необратимая правка набора, и разумно
сначала убедиться, что стандарты действительно достаются. Инструкция — в
`optional-ubrat-its/README.md`.

**Лок-файл.** `requirements-v8std.lock.txt` пуст, `scripts/gen_lockfiles.sh`
про новый файл не знает — добавьте пару
`requirements-v8std.txt:requirements-v8std.lock.txt:python:3.12-slim` в
`PAIRS` и прогоните `make lock`. До этого образ ставит зависимости по
границам; `mcp` там пришпилен точкой, так что риск невелик.

**`scripts/check_prereqs.py`** не трогал: проверка `v8std-data/` туда
просится по аналогии с `check_platform_help()`, но файл длинный, а
пропущенный корпус и так диагностируется — контейнером при старте и
командой `make v8std-check`.

**`workspace/AGENTS.md`** поправлен минимально (заменены `its_search` /
`search_all`). Файл в целом устарел на несколько заходов: ссылается на
`naparnik_*`, `templates_*`, `sonar_scan_code`, `code_search` — серверов,
которых в проекте больше нет. Это отдельная уборка, не эта.

**Патterns (`docs/patterns/`, 48 файлов про SOLID / GoF / GRASP).** Открытый
вопрос §6 плана снят сам собой: они уже в индексе v8std, отдельного решения
не требуют. Полезны ли они агенту — покажет датасет, если добавить туда
пару примеров.

**Числа не замерены.** Ни одного живого прогона не было: у меня нет доступа
к вашему стеку. Датасет написан, но не откалиброван — на «человеческих»
формулировках ожидаемые `std*` стоят в `soft` именно поэтому. Первый прогон
почти наверняка что-то покажет; правьте `values` по отчёту, а не наоборот.

## 5. Порядок приёмки

```powershell
# 1. Корпус
python scripts/fetch_v8std.py
python scripts/fetch_v8std.py --check

# 2. Сервер
docker compose up -d --build v8std-mcp
docker compose ps v8std-mcp          # ожидается healthy
curl http://127.0.0.1:8765/healthz

# 3. Инструменты (у v8std должно быть 5)
python scripts/list_tools.py

# 4. Датасет
python scripts/eval.py --dataset evals/datasets/v8std.jsonl

# 5. Мост от линтера — глазами, в Cursor:
#    «проверь этот код bsl_check_code и объясни найденные замечания
#     через стандарты»
#    Ожидается: bsl_check_code -> std_lookup.codes ->
#               v8std_explain_diagnostics -> ссылка на конкретный std
```

Признак, что заход удался: на вопрос «почему так писать нельзя» агент
отвечает номером стандарта и его текстом, а не пересказом по памяти. И
`.cursor/rules/bsl-code.mdc` при этом не растёт обратно.
