# `PERF-8b` — частичное обновление отменяло само себя

Найдено при написании раздела README про переиндексацию.

```powershell
docker compose build metadata-indexer
```

| Файл | Что |
|---|---|
| `README.md` | новый раздел «Обновление выгрузки» |
| `ИТОГИ-ЗАХОДА-4.md` | новый |
| `…/partial_fingerprint.py` | общий fingerprint в том же обходе |
| `…/apply_changes.py` | запись общего fingerprint после успеха |
| `…/tests_partial_fingerprint.py` | 52 теста (было 49) |

---

## Дефект

`apply_changes.py` обновлял своё состояние (`partial_owners_*`), но **не
трогал ключи `metadata_xml` и `bsl_source`** — те, на которые смотрит
`indexer.py` при старте.

Последствие: после каждого частичного обновления первый же
`docker compose up` видел расхождение и запускал **полную двухчасовую
переиндексацию**. Экономия в три минуты превращалась в лишние два часа.

Режим, после которого приходится ждать два часа, хуже, чем его
отсутствие. Причём заметили бы это не сразу: частичное обновление
отработало бы правильно, граф был бы верным, а расплата пришла бы при
следующем перезапуске — и связать одно с другим было бы трудно.

## Исправление

Общий отпечаток считается **в том же обходе**, что и частичный. Отдельный
проход стоил бы второго чтения диска — те же 3–12 минут, то есть удвоение
всего цикла.

Тонкость, из-за которой это могло не сработать: в общий отпечаток входят
**все** файлы с расширением, включая 2 625 без владельца. Пропусти их —
значение не совпало бы с индексерским, и расхождение осталось бы вечным,
то есть дефект бы не исчез, а спрятался. Тест
`test_matches_indexer_exactly` сверяет значение с тем, что считает сам
индексер.

При `METADATA_FINGERPRINT_STRICT=true` обновить общий отпечаток отсюда
нельзя — он считается по содержимому, а частичный обход по `stat`.
Скрипт честно предупреждает, что следующий старт будет полным.

## Ответ на вопрос: когда 2 часа, а когда 3 минуты

Записан в `README.md`, раздел «Обновление выгрузки: 3–12 минут или два
часа». Коротко:

**Решает не объём правки, а что вы запустили.** `docker compose up`
поднимает `metadata-indexer` по цепочке зависимостей — и если выгрузка
изменилась, это два часа. Частичное обновление запускается только руками,
через `apply_changes.py`.

Частичное невозможно в четырёх случаях: изменился `Configuration.xml`,
изменилось больше 300 единиц, нет сохранённого состояния (первый прогон),
сменён режим fingerprint. Скрипт сам скажет, какой именно.
