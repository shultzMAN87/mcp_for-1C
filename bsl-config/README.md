# Настройки диагностик BSL Language Server (CFG-4)

Здесь лежит `bsl-language-server.json` — набор правил, которым
`mcp-bsl-checker` проверяет код. Каталог монтируется в контейнер
`:ro`, файл читается один раз при старте.

## Почему монтируется каталог, а не файл

Docker при bind-mount **несуществующего** файла молча создаёт на его месте
**каталог**. То есть опечатка в пути дала бы не «файла нет», а «файл есть,
но это папка» — и BSL LS упал бы с невнятной ошибкой чтения. Каталог
существует в репозитории, поэтому такой ловушки нет.

## Как поменять правила

1. Правите `bsl-language-server.json`.
2. `docker compose restart mcp-bsl-checker` — пересборка образа не нужна,
   файл приезжает монтированием.
3. `bsl_stats` → секция `config`: `applied: true` и **новый**
   `fingerprint`. Если отпечаток прежний — контейнер читает старый файл.

## Про `mode: "ONLY"`

Включены **только** перечисленные диагностики; всё остальное выключено, в
том числе новые проверки, которые появятся в следующих версиях BSL LS.
Это осознанный выбор — управляемый список вместо «что дадут», — но список
придётся пополнять руками при обновлении `BSL_LS_VERSION` в
`1c-mcp-suite/Dockerfile.bsl`.

Другие режимы: `EXCEPT` (всё, кроме перечисленных), `ON` (всё по
умолчанию), `OFF` (ничего).

## Про `configurationRoot`

Путь ищется **относительно анализируемого каталога**, а не относительно
этого файла. У `bsl_check_directory` анализируемый каталог — это
`/data/1c-src` (ваш `WORKSPACE_DIR`), значит корень конфигурации должен
лежать в `<WORKSPACE_DIR>/УБД`.

Если каталога там нет, BSL LS **не сообщает об этом**: он просто не
подтягивает метаданные, и диагностики, которым они нужны, тихо не
срабатывают. Отчёт выглядит чище, чем код. Поэтому `bsl_check_directory`
проверяет это сам и кладёт в ответ `config.warning`.

Проверить руками:

```powershell
docker exec mcp-bsl-checker ls /data/1c-src
```

Если выгрузка лежит в корне `WORKSPACE_DIR` (без подкаталога `УБД`) —
уберите `configurationRoot` из файла настроек вовсе.

## Про `computeTrigger: "onSave"`

Параметр относится к режиму LSP-редактора и на пакетный анализ не влияет.
Вреда нет, смысла тоже.
