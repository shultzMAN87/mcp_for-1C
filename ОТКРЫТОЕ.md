| `FIX-27` — самолечение индексера | сама правка принята 18 августа (см. ниже, раздел «Принято»), но ветка «оба fingerprint совпали, а граф не в порядке» на живом стенде не проходилась: для этого надо оборвать фазу 2 (Ctrl+C) и запустить обычный `docker compose up`. | `FIX-28` — цифры с боевой (ждёт полной индексации) | ожидание: `632 = 631 общих модуля + 0…1 дубль`. Если дублей не ноль, сторож назовёт `module_id` поимённо — это готовый адрес дефекта в выгрузке |
| `FIX-29` — подтвердить объяснение (ждёт полной индексации) | после полного прогона в логе должна появиться строка «рёбра HAS_METHOD: строк N, из них дублей по паре 1». Если дублей ноль, а расхождение на единицу осталось — объяснение неверное и задачу надо открывать заново |
| `PERF-12` — остаток | замерено: 4705 → 642 мс. Мера приёмки (200 мс) **не выполнена**. Остаток локализован: `sum(CASE WHEN cs.resolved ...)` обходит 722 206 узлов `:CallSite`, потому что предикат по свойству счётчиками хранилища не берётся. Числа про резолв меняются только при индексации — им место в том же снимке `relation_counts`. Механизм готов, работы на полчаса |
| `MERGE` и `count(*)` — сторож `FIX-15` меряет приблизительно | 18 августа запрос перепривязки вернул `relinked = 83` при 99 фактически созданных рёбрах. `FIX-29` — тот же дефект зеркально (отчёт больше факта). Вывод: `RETURN count(*)` после `MERGE` не равен числу созданных связей ни в одну сторону, а `_query_written` в `graph_writer.py` построен именно на нём. Честное число берётся через `ON CREATE SET` с последующим подсчётом либо сравнением `count(r)` до и после. Пока не починено, любые цифры «записано N» из индексатора — оценка, а не факт |
| Формы перечислений — 28 сирот | шесть модулей форм перечислений (`Enum.*.Form.*`) не имеют узла в слое 1, привязывать их не к чему. После Захода 8 это **единственная** оставшаяся дыра во владении, и теперь она видна в `metadata_stats` как `without_owner: 28`. Решать надо на уровне разбора XML перечислений в `metadata_xml.py` |
| `SEARCH-1` шаг 3 — прогнать датасет справки | мера приёмки: `ph-030`…`ph-036` дают 7 из 7 soft, `ph-001`…`ph-023` не теряют ни одного пройденного предиката. Второе важнее первого. Множитель настраивается без пересборки: `HELP_DIALECT_WEIGHT` (1.5 по умолчанию, `1` выключает правку) |
| `EVAL-6` — сценарии 6–15 | первые пять зачтены и уже нашли `LANG-1`. Сценарий 1 переписан в явную ловушку, в «Как считать» добавлен язык ответа. `evals/manual-prompts.md`, каждый в новом чате, ~20 минут |
