## Запуск

```powershell

```

Потом применить:

```powershell
docker compose run --rm --entrypoint python metadata-indexer /app/apply_changes.py
```

У вас сейчас в плане одна изменённая единица — тот общий модуль, что вы
правили. Ожидаемое время: 3–4 минуты на обход плюс секунды на обновление.
Против 1,9 часа полной пересборки.

## Два решения, которые стоит знать

**Зависимые единицы.** `upsert_xml_file` пересобирает срез объекта целиком —
по префиксу id, то есть **вместе с узлами его модулей**. Значит после
обновления XML справочника надо заново залить его модуль объекта, модуль
менеджера и модули всех форм, даже если они не менялись. Иначе правка
одного реквизита молча уносила бы весь код объекта из графа — тихая потеря
100% кода, ровно класс `FIX-14`.

Скрипт добавляет такие единицы сам и пишет, сколько добавил.

**Порядок файлов.** XML раньше BSL, и это не косметика: если залить BSL до
XML, только что записанные узлы модуля будут снесены следующим же
обновлением объекта.

**Состояние сохраняется только после успеха.** При ошибке посреди прогона
отпечатки не пишутся — иначе они сказали бы «всё обновлено», а часть единиц
осталась бы старой, и разойтись это могло бы надолго.

## Чего этот режим не делает

Слой 2 собирается **глобальным** фикс-пойнтом: тип параметра в модуле A
зависит от вызова в модуле B. Точечное обновление такой сходимости не даёт
и дать не может.

Следствия, оба измеримы:

* вызовы **из чужих модулей** в обновлённый помечаются `resolved=false` с
  причиной `stale_after_incremental` — покрытие резолва падает;
* межмодульные типы (`:INFERRED_TYPE`) для обновлённых процедур не
  пересчитываются.

Поэтому частичный режим — «быстро и достаточно хорошо для рабочего цикла»,
**не замена полной сборке**. Скрипт печатает накопленный долг после каждого
прогона и предупреждает, когда пора прогнать полную.

Порог — `METADATA_STALE_DEBT_LIMIT`, по умолчанию 20 000. Число не с
потолка: на вашей конфигурации 722 тысячи callsite'ов, то есть 20 тысяч —
около 3% графа вызовов. Больше — и ответы про использование процедур
начнут заметно врать.

Ещё один предохранитель — `METADATA_MAX_PARTIAL` (по умолчанию 300): если
изменилось больше единиц, скрипт откажется работать точечно и скажет
запустить полную. При таком объёме полная и быстрее, и даёт корректный
глобальный резолв.

## Как проверить, что применилось

После прогона:

```powershell
@'
MATCH (c:Callable) WHERE c.module_id = 'CommonModule.ЭдоДиадокОперацииВызовСервера'
RETURN count(c) AS procedur;
MATCH (cs:CallSite) WHERE cs.reason = 'stale_after_incremental' RETURN count(cs) AS stale;
'@ | docker exec -i neo4j cypher-shell -u neo4j -p $pw
```

Первое число должно вырасти на единицу (441 → 442) — это ваша тестовая
процедура. Второе покажет первый долг.

Затем уберите процедуру из модуля и прогоните ещё раз: число должно
вернуться к 441. Это проверка на то, что удаление процедуры внутри модуля
тоже доезжает.
