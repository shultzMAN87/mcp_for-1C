# Правка кода 1С: от имён до обновлённого графа

Конфигурация проектная. Имена объектов, реквизитов, процедур и параметров
брать **только** из инструментов. Код с выдуманным именем компилируется в
голове и падает у пользователя.

Если в правке есть запрос — для него отдельный скилл `1c-query`.

## Шаг 1. Где править и с чем работать

- Объекты и реквизиты: `metadata_search` → `metadata_object_attributes`
  (`role: "dimension"` / `"resource"` для регистров).
- Существующая процедура: `code_method_signature` — параметры, директива
  (`&НаСервере`, `&НаКлиенте`), экспортность. Директиву новой процедуры
  выбирать по соседям и по месту вызова, а не по умолчанию.
- Метод платформы, в котором не уверен: `platform_help_lookup` по точному
  имени, `platform_help_search` по смыслу, `platform_help_details` — полное
  описание с параметрами и доступностью (клиент/сервер). Синтаксис по
  памяти не выдумывать.

## Шаг 2. Понять контекст

- `code_callers` (`depth: 1`) — кто зовёт процедуру. Меняешь параметры или
  возвращаемое значение — правишь и всех вызывающих, иначе сломаешь их.
  Список вызывающих при смене контракта — обязательная часть ответа.
- `code_callees` — что процедура уже вызывает: не дублировать готовое,
  переиспользовать существующие функции общих модулей.
- Нужна готовая функция общего назначения — `metadata_search` по смыслу
  в общих модулях, затем `code_method_signature`, а не своя реализация.

Для заметной правки (смена контракта, удаление, переименование) — сначала
скилл `1c-impact`.

## Шаг 3. Написать

Правила `bsl-code.mdc` и `naming.mdc` действуют. Отдельно:

- серверные обращения к базе — только в серверном контексте;
- вызов сервера с клиента — через модуль `…ВызовСервера` или серверную
  процедуру формы, а не напрямую;
- запросы в цикле — нет: собрать данные одним запросом;
- транзакция — с `Попытка … Исключение … ОтменитьТранзакцию()`.

## Шаг 4. Проверить линтером

`bsl_check_code` на изменённом фрагменте (процедура целиком, не строка).
Первая проверка в сессии идёт дольше — BSL LS поднимается.

- Нашлись замечания — коды из секции `std_lookup` одним вызовом в
  `v8std_explain_diagnostics`, исправить по требованию стандарта, проверить
  снова. Объяснять замечание по памяти не надо: «нарушен std783, вот
  требование» — то, что нужно.
- Модуль после правки целиком — `bsl_check_file` с путём внутри контейнера:
  `/data/1c-src/<путь от корня конфигурации>`, например
  `/data/1c-src/CommonModules/Мой/Ext/Module.bsl`. Windows-путь сервер не
  найдёт и честно ответит «файл не найден».
- `answerable: false` — проверка сейчас недостоверна (`bsl_stats` скажет
  почему). Не писать «замечаний нет».

Сомнение «а как положено» — `v8std_explain_snippet` на своём фрагменте:
самый точный путь от кода к стандарту.

## Шаг 5. Обновить граф — обязательно

После записи, создания или удаления файлов в `src/` — **один** вызов
`metadata_refresh` со всеми путями изменённых файлов:

```
metadata_refresh(paths=["src/CommonModules/Мой/Ext/Module.bsl", "src/Documents/X/Ext/ObjectModule.bsl"])
```

Пути — в любом виде (от `src/`, от корня конфигурации, абсолютные
Windows-пути). Без этого граф не знает о правке: `code_callers` по новой
процедуре вернёт пусто, следующий анализ влияния — неправду.

Ответ:

- `ok` — граф обновлён; по `paths` у каждого файла `reindexed`;
- `busy` — граф обновляет кто-то другой: повторить через минуту;
- `needs_full` — сказать пользователю, полную индексацию не запускать
  самому;
- `outside_config` у путей вне `src/` — норма.

Проверка, что граф видит правку: `code_method_signature` или
`code_callees` по новой/изменённой процедуре.

## Что отдавать пользователю

Код правки, список затронутых вызывающих (если менялся контракт), итог
`bsl_check_code` (чисто / какие замечания оставлены и почему) и строку
«граф обновлён» с результатом `metadata_refresh`.

## Ловушки

- `graph_empty` / `neo4j_unavailable` — остановиться, сказать, что граф
  недоступен. Имена по памяти не подставлять.
- Процедура не нашлась в графе, а в файле есть — граф отстал:
  `metadata_refresh(paths=[…])` по этому файлу, потом снова.
- Имени нет ни в графе, ни в файлах — возможно, оно в расширении или БСП,
  которых в графе нет. Не утверждать «такого нет», спросить.
