# `PERF-8` — хранение отпечатков переделано

## Что показал ваш прогон

```
INFO Neo4j отвечает (0.1 с на подсчёт узлов)
INFO   ✓ единиц 24795 … за 3.6 мин
INFO Записываем отпечатки в граф…
TimeoutError: timed out
```

База отвечает мгновенно, обход стал вчетверо быстрее (кеш прогрелся), а
запись **первых 500 строк не уложилась в 600 секунд** — прогресс-строка не
успела появиться ни разу.

Индексированная запись пятисот узлов не может занимать десять минут, когда
чтение отвечает за 0,1 с. Значит, скорость тут ни при чём.

## Две отдельные причины

**Первая, ваша — блокировки.** Предыдущие попытки (те, что перебирали
1,3 млн узлов на каждую строку) остались висеть на сервере транзакциями
записи и держат замки на узлах `:MetadataObject`. Чтение их не замечает,
запись встаёт. Проверяется одной командой:

```powershell
Measure-Command { @'
MATCH (n:MetadataObject {id: 'Catalog.Контрагенты'}) SET n.fp = 'test' RETURN count(*) AS n;
'@ | docker exec -i neo4j cypher-shell -u neo4j -p $pw }
```

Зависнет — блокировки. Лечится `docker compose restart neo4j`.

**Вторая, моя — сама схема хранения.** Я решил писать отпечаток свойством
на узел каждого владельца, потому что это «элегантно»: граф сам себе
реестр. Это рассуждение об эстетике, а не о цене. По факту — 24 795
обращений к базе на каждое сохранение данных, которые нужны всегда целиком
и сразу. Первая версия делала их запросом без метки (`PERF-4` в третий
раз), вторая — с метками, и всё равно не работала.

## Что стало

Весь набор — один JSON, разложенный по нескольким служебным узлам
`:Fingerprint` (метка уже имеет констрейнт на `kind`, ничего нового в
схему не добавляется).

| | было | стало |
|---|---|---|
| запись | 24 795 поисков по индексу | **5 запросов** |
| чтение | 1 запрос со сканом | **1 запрос** |

Сокращение набора обрабатывается: лишние куски от прошлого раза удаляются,
иначе в состоянии остались бы владельцы, которых давно нет.

Битый кусок не молчит, а пишет предупреждение: иначе его содержимое
выглядело бы как «этих объектов не было», план показал бы их новыми и
спровоцировал лишнюю работу.

**Что потеряли.** Отпечаток больше не исчезает сам вместе с удалённым
узлом. Это и не нужно: удаление определяется сравнением ключей набора с
текущим обходом — ровно так работает `build_plan`.

## Порядок

```powershell
docker compose restart neo4j
docker compose ps neo4j          # дождаться healthy
docker compose build metadata-indexer
docker compose run --rm --entrypoint python metadata-indexer /app/what_changed.py --save
```

Обход — 3–12 минут, запись после него должна занять секунды.

Затем сразу без `--save` — ожидается «изменений нет».

## Тесты

`tests_partial_fingerprint.py` — 34 теста. Всего 622.

Среди них `test_write_is_a_handful_of_queries`: на 24 795 владельцах запись
обязана уложиться в восемь запросов. Тест на цену, а не на корректность —
именно её я в прошлый раз не проверил.
