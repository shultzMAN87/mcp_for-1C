## `CI-1` — прогон одной командой

```powershell
python scripts\run_all_tests.py
```

или `make test`. На Linux — то же самое; `run_all_tests.ps1` только
запускает питоновский скрипт и пробрасывает код возврата. Дублировать
логику в двух языках значило бы обречь одну копию отстать — и отстала бы
та, которой пользуются, потому что правки идут туда, где их видно.

Сейчас: **13 наборов, 587 тестов, 7 секунд.**

**Наборы находятся сами**, по маске `tests_*.py`. Захардкоженный список
рано или поздно разошёлся бы с реальностью: новый набор просто забыли бы
дописать, и он молча не запускался бы месяцами — ровно тот класс проблем,
который Заход 4 и разбирал.

Код возврата ненулевой при любом провале. Проверено не на глаз: временно
сломал контрактный тест — скрипт вернул 1 и напечатал причину; после
восстановления вернул 0.

Наборы, требующие живой Neo4j, помечаются в выводе отдельно, чтобы «4
пропущено» не выглядело как успех.

## `BASE-1` — база в файле, а не в markdown

```powershell
python scripts\check_baseline.py            # сверить
python scripts\check_baseline.py --update   # перезаписать
```

Первый запуск создаст `evals/baseline.json` из текущего состояния графа.

**Главное отличие от прежнего способа.** В Заходе 2 сверка с базой дала
ложную тревогу: числа лежали в markdown, а выгрузка успела измениться, и
понять это было неоткуда. Здесь рядом с числами хранится **fingerprint
выгрузки**, и при расхождении скрипт прямо говорит:

```
ВНИМАНИЕ: fingerprint разошёлся с базой —
    metadata_xml: выгрузка изменилась
    Расхождение чисел ниже ОЖИДАЕМО: изменилась сама выгрузка, а не граф.
```

Это и есть разница между «база сломалась» и «база устарела» — провести её
раньше было нечем.

Допуск 5 % по умолчанию. Ноль был бы бесполезен: конфигурация живёт, сдвиг
на десяток объектов — норма. Смысл в том, чтобы поймать обвал (слой не
записался, потеряна половина рёбер), а не зафиксировать конфигурацию в
янтаре.

**Инварианты проверяются без допуска.** `orphan_Callable` — число процедур
без модуля-владельца. Сейчас это 28 (формы перечислений); рост означает,
что связь снова потеряна. Ровно `FIX-14`, который стоил 69 % слоя кода и
нашёлся случайно.

Если Neo4j недоступен, скрипт возвращает 0 и говорит об этом: отсутствие
базы — не провал тестов.

## `EVAL-1` — датасет

```powershell
python scripts\eval.py --dataset evals/datasets/metadata_graph.jsonl
```

16 примеров. `metadata-graph` и `query-builder` добавлены в маршрутизацию
`eval.py` — до сих пор ни один из них не измерялся ничем.

Что внутри:

* **поиск** — включая тот самый запрос «заказ», где `PERF-6b` требует
  документ в топ-5, а не картинку;
* **ловушки** — несуществующий объект, несуществующая процедура,
  несуществующая подсистема. Правильный ответ — «такого нет». Это половина
  ценности датасета: инструмент, который на пустоту отвечает выдумкой,
  хуже отсутствующего;
* **регрессии на пойманные дефекты** — `kind` не null (`FIX-17`), фильтр по
  русскому имени вида (`FIX-17`), `members_count` не ноль (`FIX-16`),
  `scope_warning` вместо молчания (`SCALE-1`);
* **код** — вызывающие и вызываемые для функции модуля менеджера.

**Обязательно прочтите шапку файла перед первым прогоном.** Примеры
засеяны данными из вашей приёмки 11–12 августа — теми ответами, которые вы
проверили и назвали верными. Но это проверка человеком один раз, а не
эталонный источник. Там, где предикат упадёт, сначала посмотрите, кто
неправ: инструмент или ожидание.

Неверное ожидание в датасете хуже отсутствующего — оно даёт ложное
спокойствие. Поэтому правьте `values`, а не выбрасывайте пример.

Числа привязаны к графу от 12.08.2026. Пороги я поставил с запасом
(`min: 5` там, где приёмка дала 7), чтобы обычная правка конфигурации не
красила датасет в красный.

## Чего в Заходе 4 не сделано

**`TOOL-1`** — сокращение до 12–14 инструментов. Причина неизменна:
статистики использования нет, резать вслепую не стоит. `EVAL-1` даёт
инструмент для её сбора, но не саму статистику — для этого датасет надо
сначала прогнать несколько раз в реальной работе.

**Второй прогон `EVAL-1` — «без инструментов».** План требовал мерить два
прогона, с инструментами и без, чтобы ответить на вопрос «пишет ли агент с
ними лучше». Текущий runner так не умеет: он вызывает инструменты
напрямую, а не измеряет качество ответов агента. Это отдельная работа, и
делать её вслепую, не имея ни одного прогона первого вида, было бы рано.

**Шаг «уточнить подсистему» в скилле `1c-query`** — третий пункт `SCALE-1`.
Скилл на вашей стороне, в Cursor.
