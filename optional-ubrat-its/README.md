# Опционально: убрать мёртвую ветку ИТС из platform-help

Этот каталог применяется **отдельно** и по вашему решению. Основной набор
правок без него полностью работоспособен.

## Что здесь

| Файл | Куда класть | Что меняется |
|---|---|---|
| `1c-mcp-suite/mcp-platform-help/server.py` | поверх существующего | минус ~300 строк: `its_search`, `search_all`, `_its_*`, `ITS_COLLECTION`, поля `its_*` в `platform_help_stats` |
| `1c-mcp-suite/mcp_tool_filter.py` | поверх существующего | `NO_DATA` становится пустым |

Плюс одна строка руками в `docker-compose.yml`, в сервисе
`mcp-platform-help`:

```yaml
      - ITS_COLLECTION=its_articles     # ← удалить
```

## Зачем

`DATA-1` (наполнить коллекцию `its_articles`) переносилась из плана в план
с Захода 1. После появления сервера `v8std-mcp` она закрыта, но не так, как
задумывалась: источником стандартов стал отдельный сервер со своим
корпусом. Значит, коллекция `its_articles` не появится никогда — и код,
который её читает, из «пока без данных» превращается в мёртвый по
построению.

`search_all` восстановить нельзя даже при желании: скоры двух разных
источников несопоставимы, а слияние потребовало бы сетевого вызова из
одного MCP-сервера в другой — то, чего в наборе принципиально не делают.
Разграничение источников теперь описано там, где им пользуются, — в
`.cursor/rules/mcp-tools.mdc`.

## Почему это вынесено отдельно

Это единственная необратимая правка во всём наборе: остальное добавляет,
эта — удаляет работающий (хоть и отключённый) код. Возврат — через git, но
решение всё же ваше. Разумный порядок: сначала поднять `v8std-mcp`,
убедиться, что стандарты действительно достаются, и только потом убирать
то, что они заменили.

## Проверка после применения

```powershell
docker compose up -d --build mcp-platform-help
python scripts/list_tools.py
```

Ожидается: у `help` по-прежнему 5 инструментов (`its_search` и `search_all`
и раньше были вырезаны фильтром, так что число не изменится), в логе
`[tool-filter] platform-help` больше нет строк про удалённые инструменты.
