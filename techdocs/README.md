# techdocs/ — источник правды технической документации

Р-5 вариант A: документы живут в рабочем каталоге проекта, рядом с кодом.
Каталог называется `techdocs/`, а не `docs/`, как в PLAN-DOCS: `docs/` в этом
репозитории занят документацией самого набора, и его состав стережёт
`scripts/tests_docs_canon.py`. Смешивать корпус документации по конфигурации 1С
с разборами заходов нельзя — это разные жизненные циклы и разные читатели.
Confluence получает публикации в одну сторону и источником правды не является.

## Что где лежит

| Путь | Что | Кто пишет |
|---|---|---|
| `process/`, `http-service/`, `object/` | Корпус. Здесь бывает `source: reviewed` | Только процедура ревизии, только в ветке `docs/rev-<дата>` |
| `_proposed/` | Черновики. Всегда `source: generated` | Агент во время обычной задачи — **единственное место записи** |
| `_imported/<page_id>.txt` | Исходники страниц Confluence до первой публикации | Скрипт импорта, блок H |
| `_queue/gaps.jsonl` | Заявки на документацию | `docs_gap.py` в конце задачи |
| `_queue/conflicts.jsonl` | Конфликты R4: страницу правили руками | `docs_publish.py` |
| `names.json` | Словарь имён из графа. Генерируется, руками не правится, в git не коммитится | `docs_names_dump.py` |
| `manifest.json` | Признак «репозиторий прочитан» для DOC-10 | `docs_index.py` |

## Правило записи (DOC-42)

Вне процедуры ревизии агент пишет только в `_proposed/`. Изменение файла с
`source: reviewed` вне ветки `docs/rev-*` — ошибка валидатора, а не замечание.
Причина простая: раз `techdocs/` лежит рядом с кодом, при обычной задаче агент
может незаметно поправить принятый человеком документ, и ревизия перестанет
что-либо значить.

## Имена в targets

Канон — `full_name_eng` (`Catalog.Контрагенты`). На входе валидатор терпит все
три формы (FIX-18), `--fix` приводит к канону:

```
python scripts\docs_validate.py --fix
```

Пустой `targets` — ошибка. Документ без целей нельзя поставить в очередь,
он сгниёт молча.

## Перед коммитом

```
python scripts\docs_validate.py
```

Ненулевой код возврата = коммитить нельзя. Проверка входит в `run_all_tests.py`.

## Чего здесь не бывает

- состава реквизитов — его отдаёт metadata-graph;
- планов выполнения запросов MS SQL — обоснование в PLAN-DOCS 3.6;
- утверждений, которые выводятся из имени объекта или процедуры. Пустой раздел
  с честным «замысел неизвестен» лучше пересказа сигнатуры.
